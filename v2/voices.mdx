title: Voices

---

Every agent speaks in one voice, set by `voice.voice_id`. **Every
[tier](/general/tiers) speaks through the same Mira voices**, so the catalogue
does not change with your plan.

## The catalogue

| `voice_id` | Voice |
| :--- | :--- |
| `ashu` | Male |
| `neha` | Female |
| `shruti` | Female |
| `sameer` | Male |

All four are Hindi voices that code-switch through the English of real Indian
speech. **`voice` is required** when you create an agent. Anything outside the
catalogue is rejected at agent-create time, and the error names the allowed set
so you are not left guessing:

```json title="400 Bad Request"
{
  "error": {
    "code": "invalid_request",
    "message": "unknown voice_id \"priya\" — voice.voice_id must be one of ashu, neha, sameer, shruti"
  }
}
```

<Note>
Because the catalogue is the same on every tier, an agent's voice never depends
on your plan. Moving to a different plan changes what your calls cost, not how
they sound.
</Note>

## Hearing them first

There is no `GET /v2/voices` yet. The live catalogue is the voice picker in the
[console](https://sandbox.voice.miraiminds.co) — open Agent Studio and you can
**hear each voice** before you commit to one. The name in the picker is the
`voice_id`, and the catalogue grows monthly; treat the picker, not this page, as
the source of truth.

<Tip>
**Listen before you pick.** Voice choice moves answer-through rates more than
prompt wording does.
</Tip>

## Setting a voice on an agent

```json
{
  "name": "Order confirmations",
  "system_prompt": "…",
  "voice": { "voice_id": "ashu", "language": "hi-IN" },
  "language": "hi-IN"
}
```

| Field | Type | Description |
| :--- | :--- | :--- |
| `voice_id` | string | **Required.** A voice from [the catalogue](#the-catalogue) — the same on every tier. Unknown ⇒ `400`. |
| `language` | string | Rendering language. Omit to inherit the agent's top-level `language`. **Accepted and stored, not yet honoured** — see below. |

Change it later with `PATCH /v2/agents/{id}`:

```bash
curl -X PATCH https://sandbox.voice.miraiminds.co/v2/agents/agt_… \
  -H "Authorization: Bearer sk_live_…" \
  -H "Content-Type: application/json" \
  -d '{ "voice": { "voice_id": "neha", "language": "hi-IN" } }'
```

See the [Agents reference](/v2/agents#voice) for the full agent shape.

## The language caveat

<Warning>
**`voice.language` is recorded, not yet applied**

It is validated, stored, echoed back and carried with the call payload — but
the voice renders in the agent's **top-level** `language`. Set both to the same
value and you get what you expect; set them differently and the top-level one
wins.
</Warning>

Keep `voice.language` and the agent's `language` identical.
