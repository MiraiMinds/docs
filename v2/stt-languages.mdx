Mira STT transcribes ten languages, on HTTP and on the socket alike:

| Code | Language | Status |
| :--- | :--- | :--- |
| `hi-IN` | Hindi, including Hinglish | Live |
| `en-IN` | English (Indian), for speech that is English throughout | Live |
| `gu-IN` | Gujarati | Live |
| `ta-IN` | Tamil | Live |
| `te-IN` | Telugu | Live |
| `mr-IN` | Marathi | Preview |
| `pa-IN` | Punjabi | Preview |
| `bn-IN` | Bengali | Preview |
| `kn-IN` | Kannada | Preview |
| `ml-IN` | Malayalam | Preview |

## What the status means

- **Live** is ready for production calls. Hindi with the English mixed into
  it (Hinglish), English, Gujarati, Tamil and Telugu are live, and the same
  languages are live in [text to speech](/v2/tts-languages).
- **Preview** is accepted and transcribed today, and we have not yet published
  accuracy for it. Measured numbers are published here as each language clears
  our evaluation. Test on recordings from your own callers before you rely on
  it.

The status is a label on this page only. Every language takes the same
requests, returns the same events and costs the same.

## Pass the language

Send the code you expect the speaker to use. `gu-IN` and `gu` mean the same,
in any case. When you leave it out, we transcribe Hindi.

| Where | How |
| :--- | :--- |
| [HTTP](/v2/stt-quickstart#2-one-request) | The `language` form field: `-F language=gu-IN`. The OpenAI SDK's `language="gu"` works too. |
| [WebSocket](/v2/speech-to-text#query-parameters) | `language_code` on the URL: `?language_code=gu-IN`. |
| [Pipecat](/v2/pipecat#transcribe-with-miraisttservice) | `MiraiSTTService(language="gu-IN")` |

A code outside the ten, other than `auto`, is refused with
`400 invalid_config`.

## Choose how Mira STT picks the language

| Your callers | Send | Example |
| :--- | :--- | :--- |
| Speak one language you know | That language | `language=gu-IN` |
| Mostly speak one language, and some switch to others you know | The main language, plus up to three `secondary_languages` | `language=hi-IN`, `secondary_languages=en-IN` |
| Speak a language you don't know in advance | `auto` | `language=auto` |

If you know the caller's language, pass it. A fixed language is the most
accurate and the fastest. Use `secondary_languages` when callers switch
between languages you know, such as Hindi and English, or Gujarati and Hindi.
Use `auto` only when you don't know the language.

When an utterance switches to a different language, its final transcript can
take a little longer to come back. Only that one final is slower.

### Secondary languages

`secondary_languages` lists up to three more of the ten codes, next to an
explicit `language`. It means "callers mostly speak `language`, but may switch
to these". Your `language` stays the default. An utterance moves to a
secondary language only when Mira STT is confident it is in that language. The
session remembers what it has heard, so a caller who switches is followed into
the new language.

| Where | How |
| :--- | :--- |
| HTTP | Comma-separated in a form field: `-F language=gu-IN -F secondary_languages=hi-IN,en-IN`. |
| WebSocket | Comma-separated on the URL: `?language_code=gu-IN&secondary_languages=hi-IN,en-IN`. |
| Pipecat | `MiraiSTTService(language="gu-IN", secondary_languages=["hi-IN", "en-IN"])`, from pipecat-mirai 0.7.0 |

Codes take the same forms as `language` (`hi` works too). A duplicate, or the
main language repeated, is dropped. A code outside the ten, more than three
languages, or `secondary_languages` with `auto` is refused with
`400 invalid_config`.

English words inside Hindi or Gujarati need no secondary language (see
[below](#english-inside-an-indian-language)). Add `en-IN` when callers may
switch to speaking English throughout.

A voice agent's [`secondary_languages`](/v2/agents#fields) reach Mira STT in
the same way.

### Automatic language identification

With `language=auto`, Mira STT works out the language of each utterance among
the ten and remembers what it heard earlier in the session. `unknown` means
the same, for clients written for Sarvam.

| Where | How |
| :--- | :--- |
| HTTP | `-F language=auto` |
| WebSocket | `?language_code=auto` |
| Pipecat | `MiraiSTTService(language="auto")`, from pipecat-mirai 0.7.0 |

### What to expect

- Mira STT needs a little speech before it switches. A short turn such as
  "hello" or "haan" says little about the language, so the first few turns of
  a caller who speaks a secondary language can come back in your main language
  until Mira STT is sure.
- Mira STT can't yet reliably tell Indian English apart from Tamil, Telugu,
  Kannada or Malayalam. When English and one of those are both possible, it
  keeps whichever of them you listed first. With `auto` that is English, so
  `auto` does not pick out Tamil, Telugu, Kannada or Malayalam. For callers who
  speak those languages, name the language, or add it to
  `secondary_languages` without `en-IN`.

### The language in the answer

| Where | Field |
| :--- | :--- |
| HTTP | `language` in the `json` and `verbose_json` answers: the language of most of the speech in the clip. In `verbose_json`, each segment also has its own `language`. |
| WebSocket | `language` on `transcript.partial` and `transcript.final`, in an `auto` or secondary-language session: the language of that utterance. |
| Pipecat | `TranscriptionFrame.language`, the language of that utterance. |

```json title="HTTP, language=auto"
{ "text": "નમસ્તે મારે કાલે સાંજે પાંચ વાગ્યાની appointment બુક કરવી છે", "language": "gu-IN" }
```

```json title="WebSocket, language_code=auto"
{ "event": "transcript.final", "utterance_idx": 3, "text": "हाँ ठीक है कल शाम को आ जाइए", "language": "hi-IN" }
```

### Change the language mid-session

On the socket, send `config.update` with `language_code`,
`secondary_languages` or both. It applies from the next utterance; the
utterance in progress finishes with the settings it started with:

```json
{ "event": "config.update", "language_code": "ta-IN", "secondary_languages": "en-IN" }
```

`"secondary_languages": ""` clears the list. To move to `auto` from a session
with secondary languages, clear them in the same message:
`{"event": "config.update", "language_code": "auto", "secondary_languages": ""}`.
On HTTP, each request carries its own `language` and `secondary_languages`.

## English inside an Indian language

Indian speech mixes in English all the time. Pass the Indian language, and the
English words in it come back in English, in Latin script, the way they were
said. Nothing is translated, and the rest stays in the language's own script:

```text title="hi-IN"
नमस्ते मुझे कल शाम पाँच बजे का appointment book करना है
```

```text title="gu-IN"
નમસ્તે મારે કાલે સાંજે પાંચ વાગ્યાની appointment બુક કરવી છે
```

English inside Hindi or Gujarati is part of that language, so you don't need
`en-IN` for it. Use `en-IN` when the speaker talks English throughout.

## When to use offline transcription instead

[Offline transcription](/v2/transcriptions) is a separate service for
recordings that already exist. Use it when you need speaker labels, timestamps
across a long call, or recordings of up to two hours. It has its own `auto`,
which detects the main language of the recording, and its own codes: `hi`,
`gu`, `en`, `mr`, `pa`, `bn` and `ur`. For one clip of up to two minutes, or live audio, use the
[speech-to-text API](/v2/stt-quickstart).

## Ask for a language

If your callers speak a language that is not here, or a preview language
matters to your business, tell your Mirai contact which one.
