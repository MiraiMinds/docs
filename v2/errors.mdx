## Money and access

These five stop calls for a reason only you can fix. Each has one fix.

| `error.code` | Status | What happened | Fix |
| :--- | :--- | :--- | :--- |
| `insufficient_balance` | `402` | Out of credit | [Add credit or go live](#out-of-credit) |
| `access_expired` | `403` | Your sandbox ended | [Go live](https://sandbox.voice.miraiminds.co/#/live) |
| `production_workspace_required` | `403` | Sandbox key on production | [Go live first](/v2/go-live) |
| `contract_unavailable` | `403` | Tier outside your plan | [Leave `tier` out](/general/tiers#setting-the-tier) |
| `forbidden` | `403` | Key revoked | Create a new key in Developers: [sandbox](https://sandbox.voice.miraiminds.co/#/developers) or [live](https://console.voice.miraiminds.co/#/developers) |

- **`insufficient_balance`**: the wallet can't cover one minute of the call,
  or it is empty when you generate a flow, transcribe or call the language
  model. Nothing was dialled, run or charged. Inside a running
  [campaign](/v2/campaigns) this is not an error: the campaign pauses with
  `pause_reason: "insufficient_balance"`.
- **`access_expired`**: the sandbox's end date has passed, so its keys stop.
  The message gives the date. See [when a sandbox ends](/v2/go-live#when-a-sandbox-ends).
- **`production_workspace_required`**: a key from a workspace that has not
  gone live was sent to `https://prod.voice.miraiminds.co`. Use
  `https://sandbox.voice.miraiminds.co` until you go live.
- **`contract_unavailable`**: `tier` is not your company's plan, or the company
  has not finished going live. Nothing was dialled. Calls default to your
  plan's tier.

## The error envelope

Most v2 errors use the envelope below. Two validation errors are exceptions:
[tool definitions](/v2/tools#validation-and-runtime-errors) return
`{"error":"invalid_tools","details":[...]}` and
[node graphs](/v2/node-agents#errors) return
`{"error":"invalid_flow","details":[...]}`, each with every offending field
path. [Flow generation](/v2/node-agents#generation-errors) uses the same shape
for `flow_generation_failed`.

```json
{
  "error": {
    "code": "invalid_request",
    "message": "to must be an E.164 phone number, got '9876543210'"
  }
}
```

| Field | Description |
| :--- | :--- |
| `code` | Stable, `snake_case`, machine-readable. **Branch on this.** |
| `message` | Written for a developer reading a log. It is not stable, so never parse it or show it to an end user verbatim. |

## Status codes

| Status | Meaning | Retry? |
| :--- | :--- | :--- |
| `400` | The request is malformed or a field is invalid. | No. Fix the request. |
| `401` | Missing, malformed or unknown key, or an invalid token on a browser call's media link, a call's events link or a [speech stream](/v2/speech-compatibility#browser-stream-tokens). | No. |
| `402` | The wallet can't cover the call or request. | After you add credit. |
| `403` | The key is revoked, the sandbox has ended, the request is outside your plan, recording is off, or [sub-workspaces](/v2/sub-workspaces) are off or archived. | No. |
| `404` | No such resource in your workspace, including one that exists in someone else's. | No. |
| `409` | State conflict: the same `Idempotency-Key` still in flight, or an operation the current state forbids. | No. |
| `413` | The request body, or a file you sent by link, is over the endpoint's limit. | No. Send a smaller request. |
| `415` | [Speech to text](/v2/stt-quickstart#when-something-fails) could not decode the audio file. | No. Send WAV or a common format. |
| `422` | Valid request, but no usable result: a flow that stayed invalid, a recording with no conversation, or a [Realtime session](/v2/realtime#errors) for an agent with a custom voice. | Not as is. |
| `426` | A plain HTTP request reached a WebSocket endpoint. | No. Connect with a WebSocket client. |
| `429` | Request-rate limit, or no capacity (`at_capacity`). Reaching your *call* concurrency limit does not return `429`: those calls queue. A [Realtime session](/v2/realtime#errors) cannot queue, so it gets `429 concurrency_limit`. | Yes, with backoff. |
| `500` | Our fault. | Yes, with backoff. |
| `501` | The feature exists in the contract but is not live yet. | No. |
| `502` | A model behind the request failed (`upstream_error`), or a Realtime session was admitted but could not start (`admission_incomplete`). Nothing was charged. | Yes. |
| `503` | Temporarily unavailable, or a feature not provisioned for your workspace. | Yes, except `campaigns_unavailable` and `transcription_unavailable`. |
| `504` | [Speech to text](/v2/stt-quickstart#when-something-fails) over HTTP timed out (`upstream_timeout`). Nothing was charged. | Yes. |

## Error codes

Grouped by area. Each links to the page with the detail.

### Requests and keys

| `error.code` | Status | When | Fix |
| :--- | :--- | :--- | :--- |
| `invalid_request` | `400` | A field is missing, the wrong type or out of range, or the JSON is malformed. | Read `message`; it names the field. |
| `unauthorized` | `401` | No `Authorization` header, no `Bearer ` prefix, or an unknown key. | Check the header. A trailing newline from `cat`-ing a key file is the usual culprit. |
| `invalid_token` | `401` | A [browser call](/v2/web-calls)'s media link, a call's [events link](/v2/live-events) or a [TTS stream](/v2/tts-websocket#from-a-browser) token is unknown, expired or already used. | Use links exactly as returned, and mint a new stream token for each connection. |
| `not_found` | `404` | Unknown or deleted ID, or one from another workspace. | Check the ID. For a transcript or recording, check `transcript_available` / `recording_available`. |
| `recording_disabled` | `403` | `recording_enabled: true` on a workspace with recording off. Nothing was created. | Leave it out, or send `false`. |
| `request_too_large` | `413` | Over the endpoint's size limit: 25 MB for a [flow recording](/v2/node-agents#transcribe-a-recording) or an [STT clip](/v2/stt-quickstart#limits); 45 MB upload or 200 MB link for [offline transcription](/v2/transcriptions#errors). Nothing was charged. | Send a smaller file, such as mono mp3, or a large one by link. |
| `upgrade_required` | `426` | A plain HTTP request reached a WebSocket endpoint. | Connect with `wss://`. |

### Calls

| `error.code` | Status | When | Fix |
| :--- | :--- | :--- | :--- |
| `duplicate_call` | `409` | A request with this `Idempotency-Key` is still being processed. | Not an error on a retry. No second call was placed. |
| `conflict` | `409` | Not allowed in the current state, such as aborting a call that has ended. | Read the resource's `status` first. |
| `call_not_active` | `409` | A [live control](/v2/web-calls#live-control) reached a call that is not in progress. | Wait for `call.started`. |
| `unsupported_channel` | `400` | A live control reached a call that is not a browser call. | Stop a phone call with [`POST /abort`](/v2/calls#abort-a-call). |
| `flow_agent_voice_only` | `409` | A text chat named a [node-based agent](/v2/node-agents). | Use `phone` or `web`. |
| `flow_first_message_unsupported` | `409` | A call sent `first_message` for a node-based agent. | Leave it out; personalise with `variables`. |
| `flow_system_prompt_unsupported` | `409` | A call sent a [per-call `system_prompt`](/v2/calls#per-call-prompt) for a node-based agent. | Leave it out; personalise with `variables`. |
| `tier_unavailable` | `501` | `tier` names a tier not enabled here. | Leave `tier` out. |

### Realtime sessions

A [Realtime session](/v2/realtime) that cannot start fails its WebSocket upgrade
with an error code. Most are the codes on the rest of this page, such as
`insufficient_balance` or `workspace_not_found`. The codes below are Realtime's
own. [Realtime errors](/v2/realtime#errors) lists every code a session can
return, before it starts and while it runs.

| `error.code` | Status | When | Fix |
| :--- | :--- | :--- | :--- |
| `missing_api_key` | `401` | The upgrade carried no key. | Send `Authorization: Bearer sk_live_…`, or the key as a subprotocol. |
| `flow_agent_realtime_unsupported` | `409` | `agent_id` names a [node-based agent](/v2/node-agents). | Use a single-prompt agent, or leave out `agent_id`. |
| `session_ended` | `409` | The session ended before it started. | Open a new one. |
| `voice_not_supported` | `422` | The agent speaks in a [custom voice](/v2/custom-voices), which Realtime can't run yet. | Use an agent with a [built-in voice](/v2/voices). |
| `admission_incomplete` | `502` | The session was admitted but could not start. Nothing was charged. | Try again. |
| `worker_unavailable` | `503` | No voice worker could take the session. Nothing was charged. | Honour `Retry-After` (1 s). |
| `start_timeout` | `504` | Setting up the session took longer than about 8 seconds, often because of slow pre-call tools. | Try again. |

### Capacity and outages

| `error.code` | Status | When | Fix |
| :--- | :--- | :--- | :--- |
| `rate_limited` | `429` | Request rate, a full queue (500 calls), or an hourly limit on [flow generation](/v2/node-agents#generate-a-flow-from-a-brief) or [offline transcription](/v2/transcriptions#errors). `message` says which. Your call *concurrency* never causes it. | Honour `Retry-After`. See [Limits](/v2/limits). |
| `at_capacity` | `429` | No capacity: every line is busy, or your workspace is at its [TTS](/v2/tts-quickstart#limits), [stream](/v2/tts-websocket) or [offline transcription](/v2/transcriptions#errors) limit. Nothing was charged. | Honour `Retry-After` and retry. |
| `concurrency_limit` | `429` | A [Realtime session](/v2/realtime#limits) found no free voice slot. Sessions are never queued. Nothing was charged. | Honour `Retry-After` (5 s) and connect again. |
| `upstream_unavailable` | `503` | A service we depend on is briefly down. A flow generation whose model had answered is charged for what it did. | Honour `Retry-After` and retry. |
| `upstream_error` | `502` | The model failed: [TTS](/v2/tts-quickstart#when-something-fails) or the [language model](/v2/llm#when-something-fails). Nothing was charged. | Retry. Quote `X-Request-Id` or `correlation_id` to us. |
| `upstream_timeout` | `504` | [Speech to text](/v2/stt-quickstart#when-something-fails) over HTTP did not finish in time. Nothing was charged. | Retry. Send long clips to [offline transcription](/v2/transcriptions). |
| `status_unavailable` | `503` | The [status API](/v2/status#read-incidents-with-the-api) could not read incident records for a moment. | Retry after a short wait. [status.miraiminds.co](https://status.miraiminds.co) still works. |
| `internal` | `500` | Our bug. It has already alerted us. | Retry with backoff. If it persists, [send us the `call_id`](mailto:help@miraiminds.co?subject=Error%20500). |

<Note>
`error.code` is an **open enum**. We add new codes without a version bump, so
always keep a default branch keyed on the HTTP status.
</Note>

<Warning>
**Foreign IDs are `404`, never `403`**

An `agt_`, `call_`, `cmp_` or `trn_` ID that exists in another workspace is
answered exactly as an ID that never existed: `404 not_found`. Any other answer would be an
enumeration oracle, letting someone probe which IDs are real on the platform by
watching the status code change. A `Mirai-Workspace` value that names a
workspace outside your own is answered the same way, with
`404 workspace_not_found`. `403` never means "someone else's ID". It means your
own key has been revoked, your sandbox has ended (`access_expired`), your
workspace is not allowed what the request asks for (`contract_unavailable`,
`production_workspace_required`, `recording_disabled`, `sub_workspaces_disabled`),
or you archived the sub-workspace you named (`workspace_archived`).
</Warning>

## Handling errors

To handle every error, branch on the status first and then on the code.

<Tabs>
  <Tab title="Python">
    ```python
    import random
    import time

    import httpx


    class MiraiError(Exception):
        def __init__(self, status: int, code: str, message: str):
            super().__init__(f"{status} {code}: {message}")
            self.status, self.code, self.message = status, code, message


    RETRYABLE = {429, 500, 502, 503, 504}


    def request(client: httpx.Client, method: str, path: str, **kw) -> dict:
        for attempt in range(5):
            r = client.request(method, path, **kw)
            if r.is_success:
                return r.json() if r.content else {}

            body = r.json() if r.headers.get("content-type", "").startswith("application/json") else {}
            err = body.get("error", {})

            if r.status_code in RETRYABLE and attempt < 4:
                # honour Retry-After when we send it, else exponential + jitter
                wait = float(r.headers.get("Retry-After", 2**attempt))
                time.sleep(wait + random.random())
                continue

            raise MiraiError(r.status_code, err.get("code", "unknown"), err.get("message", r.text))

        raise MiraiError(r.status_code, "retries_exhausted", "gave up after 5 attempts")
    ```

    At the call site, only two codes need their own branch:

    ```python
    try:
        call = request(client, "POST", "/v2/calls", json=payload,
                       headers={"Idempotency-Key": key})
    except MiraiError as e:
        if e.code == "insufficient_balance":
            pause_campaign(); alert_ops(e.message)
        elif e.code == "duplicate_call":
            pass                     # same key still in flight — no second call
        else:
            raise
    ```

  <Tab title="Node.js">
    ```javascript
    export class MiraiError extends Error {
      constructor(status, code, message) {
        super(`${status} ${code}: ${message}`);
        this.status = status;
        this.code = code;
      }
    }

    const RETRYABLE = new Set([429, 500, 502, 503, 504]);
    const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

    export async function request(path, init = {}, attempt = 0) {
      const res = await fetch(`https://sandbox.voice.miraiminds.co${path}`, {
        ...init,
        headers: {
          Authorization: `Bearer ${process.env.MIRAI_API_KEY}`,
          "Content-Type": "application/json",
          ...init.headers,
        },
      });

      if (res.ok) return res.status === 204 ? null : res.json();

      const body = await res.json().catch(() => ({}));
      const { code = "unknown", message = res.statusText } = body.error ?? {};

      if (RETRYABLE.has(res.status) && attempt < 4) {
        const retryAfter = Number(res.headers.get("Retry-After"));
        const wait = (Number.isFinite(retryAfter) ? retryAfter : 2 ** attempt) * 1000;
        await sleep(wait + Math.random() * 1000);
        return request(path, init, attempt + 1);
      }

      throw new MiraiError(res.status, code, message);
    }
    ```

    At the call site:

    ```javascript
    try {
      const call = await request("/v2/calls", {
        method: "POST",
        headers: { "Idempotency-Key": key },
        body: JSON.stringify(payload),
      });
    } catch (e) {
      if (e.code === "insufficient_balance") {
        await pauseCampaign();
        await alertOps(e.message);
      } else if (e.code !== "duplicate_call") {
        throw e; // duplicate_call means the same key is still in flight
      }
    }
    ```

### Retry rules

- **Retry** `429`, `500`, `502`, `503`, `504` and network errors. Use
  exponential backoff with jitter, and honour `Retry-After` when present.
- **Never retry** `400`, `401`, `403`, `404`, `501`. The same request will fail
  the same way. `503 campaigns_unavailable` and `503 transcription_unavailable`
  belong in this group too, because they clear only when the feature is
  provisioned.
- **`402` is retryable only after you add credit**, not on a timer. See
  [Out of credit](#out-of-credit).
- **Always send `Idempotency-Key` on `POST /v2/calls`.** A timeout does not
  tell you whether the phone rang, and without the key, your retry places a
  second call to a real person.

### What a `409 duplicate_call` actually means

A request with this `Idempotency-Key` is **still being processed**. This only
happens in a narrow race and is not the normal retry path. We cannot replay a
response that has not been produced yet, and we must not place a second call,
so we return this error instead.

When the original request completes, the same key replays its stored response,
so a retry a moment later returns the original `202` and the original `call_id`.
In both cases **no second call is placed**. For a retry this is usually a
*success*, so log it and move on instead of showing it to your users as an
error.
