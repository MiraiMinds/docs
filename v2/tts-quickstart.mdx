description: Create a key and get Hindi audio from one curl request in two minutes, then call the same endpoint from your own orchestrator.

This is the voice our agents use, offered as a standalone API. It speaks
OpenAI's `POST /v1/audio/speech` protocol, so every OpenAI SDK and every
framework with an OpenAI TTS integration can already call it. You change the
base URL and the model name, and the rest of your code stays as it is.

## 1. Get a key

Sign in to the [console](https://sandbox.voice.miraiminds.co) with your access
code, open **Developers**, and create an API key. It is a `sk_live_` secret,
and the console shows it only once. We store only its hash, so we cannot
recover a lost key; you rotate it instead. The same key works for TTS and the
rest of the [v2 API](/v2/overview), and draws on the same [wallet](/v2/wallet).

## 2. First audio

```bash
curl https://sandbox.voice.miraiminds.co/v1/audio/speech \
  -H "Authorization: Bearer $MIRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mira-tts",
    "voice": "ashu",
    "response_format": "wav",
    "input": "नमस्ते, मैं आशु बोल रहा हूं। आपका ऑर्डर तैयार है।"
  }' \
  --output speech.wav
```

The response body is the audio itself. Keep `--output`: without it, curl
prints 300 KB of binary into your terminal and you have to reset it. If
`speech.wav` plays, the integration works, and the sections below refine it.

There are exactly two formats:

| `response_format` | You get |
| :--- | :--- |
| `wav` | A playable file: 48 kHz mono PCM16 with a header. |
| `pcm` | The same samples, raw and streamed. The first bytes arrive while the rest is still rendering. Use this for anything live. |

Any other value, including OpenAI's default `mp3`, returns a 400 that names
these two. Always send `response_format` explicitly.

<Note>
**One model name.** `model` is `mira-tts`. The old build-numbered name,
`mira-tts-v51`, is still accepted as an alias, so existing callers keep
working. Any other value returns a `404`.
</Note>

The same endpoint is also mounted at `POST /v2/tts` if you would rather keep
every URL under `/v2`. It runs the same handler and also accepts `text` as an
alias of `input`. Auth, fields, headers and billing are identical, so switching
between the two changes only the URL.

## 3. Pick a voice

```bash
curl https://sandbox.voice.miraiminds.co/v2/voices \
  -H "Authorization: Bearer $MIRA_API_KEY"
```

The voices today are `ashu`, `neha`, `shruti` and `sameer`. All four are Hindi
voices that code-switch into English the way real Indian speech does. `neha` is
the default if you omit `voice`. Each entry gives the `voice_id`, the voice's
name and its language. To hear a voice before you choose, use the voice picker
in the console's Agent Studio. An unknown voice returns a 400 that names the
allowed set; we never swap in another voice silently. Gujarati is accepted in
beta, and five more languages are on the way. See the
[language roadmap](/v2/tts-languages).

## 4. Stream it with the OpenAI SDK

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk_live_...",
    base_url="https://sandbox.voice.miraiminds.co/v1",
)

with client.audio.speech.with_streaming_response.create(
    model="mira-tts",
    voice="ashu",
    response_format="pcm",
    input="चलिए numbers से start करते हैं।",
) as response:
    for chunk in response.iter_bytes():
        ...  # raw s16le mono @ 48 kHz — feed your player as it arrives
```

## 5. Drop it into your orchestrator

If you build on Pipecat, use our integration. Install it with
`uv add pipecat-mirai` and add the service to your pipeline:

```python
import os
from pipecat_mirai import MiraiTTSService

tts = MiraiTTSService(
    api_key=os.environ["MIRA_API_KEY"],
    settings=MiraiTTSService.Settings(voice="ashu"),
)
```

It handles sample rates and interruptions for you, and has a one-line fix for
choppy audio on phone calls. See [Pipecat](/v2/pipecat) for the full setup.

Other frameworks with an OpenAI TTS integration can call the endpoint directly.
Point them at `https://sandbox.voice.miraiminds.co/v1` with model `mira-tts`
and `response_format="pcm"`, and treat the audio as 48 kHz.

## What comes back

Every `200` carries its own accounting in headers, so you can meter spend and
pin a build without a second request:

| Header | Meaning |
| :--- | :--- |
| `X-Request-Id` | This request's id (`tts_…`). It identifies the row in your [request log](#your-request-log) and is the `reference` on the [ledger row](#billing). |
| `X-Chars-Billed` | Characters counted for billing. |
| `X-Cost-Paise` | What this request costs, in paise, once it completes. |
| `X-Sample-Rate` | Always `48000`. |
| `X-Mira-Model` | The build that produced the audio, for example `miraiminds/mira-tts-v53`. Pin it when you compare quality across releases. |

Every error after authentication also carries `X-Request-Id`, so you can trace
a failure the same way as a success. Quote the id when you ask us about a
failed request.

## Limits

| Limit | Default | Over the limit |
| :--- | :--- | :--- |
| Requests in flight | Your workspace's limit, **10** unless it has been set otherwise | `429 at_capacity` with a `Retry-After` header. |
| `input` length | **2,000 characters** | `400 invalid_request`. Split longer text. |
| Request rate | Per key (see [Limits](/v2/limits)) | `429 rate_limited` with a `Retry-After` header. |

We refuse a request over the limit instead of queueing it. Honour
`Retry-After` and send it again. A refused request does not hold a slot and
costs nothing. `at_capacity` can also come from a deployment-wide ceiling when
the speech node is saturated. Handle it the same way.

The limit is set per workspace, and a workspace starts at 10. The plans under
[Billing](#billing) list the concurrency each plan includes. If your
workspace's limit doesn't match your plan, or you need more, ask your Mirai
contact. Changing the limit is a provisioning change and needs no change to
your code.

Each request is rounded up to the paisa, and we charge only for completed
audio. If the engine fails, the stream stalls or your client disconnects
part-way, nothing is charged and no ledger row is written. The request still
appears in your log, with a status that says why.

The charge is one debit row on the same [wallet](/v2/wallet) your calls draw
from, and it appears on the console billing statement under **Text to speech**:

```json title="GET /v2/wallet/transactions"
{
  "id": "txn_01K4N7Q2R5S8T4V7W9X1Y3ZB6C",
  "object": "wallet_transaction",
  "type": "debit",
  "amount_inr": 0.12,
  "balance_after_inr": 498.32,
  "call_id": null,
  "kind": "tts",
  "reference": "tts_01K4N7Q0V8ZR3M6D9F2H5J7K1P",
  "quantity": 62,
  "description": "Text to speech · 62 characters · shruti",
  "created_at": "2026-09-09T09:16:39Z"
}
```

| Field | Meaning |
| :--- | :--- |
| `kind` | `tts` here, `call` on call rows. Classify rows by this field, never by reading `description`. |
| `reference` | The `X-Request-Id` of the request that produced the audio. |
| `quantity` | Characters billed. This is the same number as `X-Chars-Billed`. |

If your wallet cannot cover the request, you get a `402` before anything is
synthesised. See [Wallet](/v2/wallet#list-transactions).

## Your request log

We log every request, whether it completed, failed or was rejected, and you can
read the log yourself.

```bash
curl "https://sandbox.voice.miraiminds.co/v2/tts/requests?limit=50" \
  -H "Authorization: Bearer $MIRA_API_KEY"
```

```json title="200 OK"
{
  "id": "tts_01K4N7Q0V8ZR3M6D9F2H5J7K1P",
  "object": "tts_request",
  "created_at": "2026-09-09T09:16:39Z",
  "source": "api",
  "voice": "shruti",
  "model": "mira-tts",
  "format": "pcm",
  "chars": 62,
  "status": "completed",
  "cost_inr": 0.12,
  "first_byte_ms": 93,
  "total_ms": 3210,
  "bytes": 437760,
  "preview": "नमस्ते, मैं शालिनी बोल रही हूँ …",
  "error_code": null
}
```

Rows come newest first, and only from your own workspace:

| Query | Meaning |
| :--- | :--- |
| `limit` | Up to 200, default 50. |
| `cursor` | Opaque, from the response's `next_cursor`. |
| `from`, `to` | RFC3339 timestamps. |
| `status` | `completed`, `failed`, `truncated` or `rejected`. |
| `source` | `api` or `playground`. |

`GET /v2/tts/requests/{id}` returns a single row. The id is the
`X-Request-Id` you got back from the request.

| Field | Meaning |
| :--- | :--- |
| `status` | `completed` (audio relayed in full), `failed` (nothing usable), `truncated` (the stream stopped part-way), `rejected` (refused before synthesis because of a bad field, no balance or no free slot). |
| `source` | `api` for a request made with your key. `playground` for audio from the console's **Hear it** button. Playground requests are logged like any other but never charged, so `cost_inr` is `0`. |
| `cost_inr` | What it cost. `0` unless `completed`. |
| `first_byte_ms` | Time to the first audio byte. In a live pipeline, this is the number to watch. |
| `total_ms`, `bytes` | Wall time and audio size for the whole request. |
| `error_code` | The `error.code` that was returned, or `null`. |

<Note>
**We do not keep the text you send.** `preview` is the first 48 characters of
`input`, so a row is recognisable in a list. The rest is never stored.
</Note>

The same table is in the console under **TTS → Requests**, if you would rather
check it there than poll the API.

## When something fails

| Status | `code` | Cause |
| :--- | :--- | :--- |
| 400 | `invalid_request` | Empty `input`, more than 2,000 characters, an unknown voice, or a `response_format` other than `wav` / `pcm`. The message names the valid values. |
| 401 | `unauthorized` | Missing or unknown key. Check the `Authorization: Bearer sk_live_…` header. |
| 402 | `insufficient_balance` | The wallet cannot cover this request. Nothing was synthesised and nothing was charged. |
| 404 | `model_not_found` | `model` is neither `mira-tts` nor the `mira-tts-v51` alias. |
| 429 | `at_capacity` | You already have as many requests in flight as your workspace allows (10 unless it has been set otherwise), or the deployment is saturated. Honour `Retry-After`. |
| 429 | `rate_limited` | Per-key request rate. Honour `Retry-After`, and see [Limits](/v2/limits). |
| 502 | `upstream_error` | The engine refused, returned no audio, or the stream stalled past its timeout. Nothing was charged; the message says which. Retry. |

Errors use the same envelope as the rest of the API. See
[Errors](/v2/errors). If you are stuck on something this page does not cover,
reply on your onboarding thread, where a person reads it.
