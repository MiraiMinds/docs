Voice Infra is **prepaid**. Every workspace has one INR wallet, and everything
below draws on it.

| What | Charged |
| :--- | :--- |
| Calls | When the call ends |
| [Text to speech](/v2/tts-quickstart#billing) | When a request completes |
| [Speech to text](/v2/stt-quickstart#billing) | For the audio received |
| [Offline transcription](/v2/transcribe-recorded-calls#pricing) | When a job completes |
| [AI flow drafts](/v2/node-agents#what-a-draft-costs) | When a draft finishes |

[Recording transcriptions](/v2/node-agents#what-transcription-costs) for a flow
are charged like drafts. Top-ups credit the wallet at once. If it cannot cover
a minute, `POST /v2/calls` returns [`402`](#402-insufficient-balance) and no
call is placed. Rates and 10-second blocks are on
[Billing & tiers](/general/tiers).

## Get balance

```http
GET /v2/wallet
```

<Tabs>
  <Tab title="cURL">
    ```bash

      -H "Authorization: Bearer sk_live_YOUR_API_KEY"
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import os, httpx

                  .raise_for_status().json()
    print(wallet["balance_inr"])  # 500
    ```
  </Tab>
  <Tab title="Node.js">

    ```javascript
    const auth = { Authorization: `Bearer ${process.env.MIRAI_API_KEY}` };

    const wallet = await fetch(`${API}/v2/wallet`, { headers: auth }).then((r) => r.json());
    console.log(wallet.balance_inr); // 500
    ```
  </Tab>
</Tabs>

```json title="200 OK"
{
  "balance_inr": 1200,
  "balance_paise": 120000,
  "currency": "INR",
  "updated_at": "2026-11-16T05:00:00Z",
  "reserved_for_renewals_inr": 3000,
  "reserved_for_renewals_paise": 300000,
  "held_for_calls_inr": 60,
  "held_for_calls_paise": 6000,
  "renewal_reserve": { "enabled": true, "days_before": 7 }
}
```

| Field | Type | Description |
| :--- | :--- | :--- |
| `balance_inr`, `balance_paise` | number, integer | Spendable balance: what new calls and requests can use now, after every hold below. Never negative. |
| `currency` | string | Always `INR`. |
| `updated_at` | string | When the balance last changed. |
| `reserved_for_renewals_inr`, `reserved_for_renewals_paise` | number, integer | Held for number renewals coming up, when [renewal reserve](#wallet-settings) is on. `0` when it is off. |
| `held_for_calls_inr`, `held_for_calls_paise` | number, integer | Held for calls running now: each call's worst-case charge, until it ends and is charged. |
| `renewal_reserve` | object | Your [renewal reserve](#wallet-settings) setting: `enabled` and `days_before`. |
| `spend` | object | Only on a request with a sub-workspace's `Mirai-Workspace` header: that brand's [spending limit and usage](/v2/sub-workspaces#see-how-much-of-the-limit-is-used). |

Held money is still yours and still in the wallet. It just can't be spent on
anything else until it is charged or released.

<Tip>
**Alert on this, don't discover it**

Poll the balance on a schedule (hourly is plenty) and alert your own team below
a threshold that covers a day of traffic. A `402` in the middle of a campaign is
a much worse way to learn you are out of credit.
</Tip>

## Wallet settings

```http
GET   /v2/wallet/settings
PATCH /v2/wallet/settings
```

Wallet settings hold one choice today: **renewal reserve**. When it is on, the
₹1,500 for each Mirai number that renews automatically is held in your wallet a
few days before its renewal, so calls can't spend the money the number needs.
It is off until you turn it on. See
[Reserve renewals ahead of time](/v2/phone-numbers#reserve-renewals-ahead-of-time).

```bash
curl -X PATCH https://prod.voice.miraiminds.co/v2/wallet/settings \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "renewal_reserve": { "enabled": true, "days_before": 7 } }'
```

```json title="200 OK"
{
  "object": "wallet_settings",
  "renewal_reserve": { "enabled": true, "days_before": 7 },
  "updated_at": "2026-11-16T05:00:00Z"
}
```

| Field | Type | Description |
| :--- | :--- | :--- |
| `renewal_reserve.enabled` | boolean | Hold renewals ahead of time. Default `false`. |
| `renewal_reserve.days_before` | integer | How many days before a renewal to hold its amount: `1` to `30`. Default `7`, the day of the first renewal reminder. |
| `updated_at` | string \| null | When the settings last changed. `null` if they never have. |

- Send either field on its own. A field you leave out keeps its value.
- Turning the reserve off releases every renewal hold at once.
- The settings belong to your account. A request with a sub-workspace's
  `Mirai-Workspace` header can read them, but a `PATCH` with that header
  answers `400 invalid_request`: change them from your account.
- A workspace that has not [gone live](/v2/go-live) has no production wallet,
  so both routes answer `409 production_wallet_required`.

## List transactions

```http
GET /v2/wallet/transactions?limit=&cursor=
```

The ledger. One row per credit or debit, newest first.

<Tabs>
  <Tab title="cURL">
    ```bash
    curl "https://sandbox.voice.miraiminds.co/v2/wallet/transactions?limit=50" \
      -H "Authorization: Bearer sk_live_YOUR_API_KEY"
    ```
  </Tab>
  <Tab title="Python">
    ```python
    def all_transactions():
        cursor = None
        while True:
            params = {"limit": 100, **({"cursor": cursor} if cursor else {})}
            page = httpx.get(
                f"{API}/v2/wallet/transactions", headers=auth, params=params, timeout=30
            ).raise_for_status().json()
            yield from page["data"]
            if not page["has_more"]:
                return
            cursor = page["next_cursor"]

    spent = sum(t["amount_inr"] for t in all_transactions() if t["type"] == "debit")
    ```
  </Tab>
  <Tab title="Node.js">
    ```javascript
    async function* allTransactions() {
      let cursor = null;
      for (;;) {
        const qs = new URLSearchParams({ limit: "100", ...(cursor ? { cursor } : {}) });
        const page = await fetch(`${API}/v2/wallet/transactions?${qs}`, { headers: auth })
          .then((r) => r.json());
        yield* page.data;
        if (!page.has_more) return;
        cursor = page.next_cursor;
      }
    }

    let spent = 0;
    for await (const t of allTransactions()) if (t.type === "debit") spent += t.amount_inr;
    ```
  </Tab>
</Tabs>

| Field | Type | Description |
| :--- | :--- | :--- |
| `type` | `credit` \| `debit` | Direction. |
| `amount_inr` | number | Always positive; read `type` for direction. |
| `balance_after_inr` | number | Balance immediately after this row. |
| `call_id` | string \| null | Set on call debits, `null` on top-ups and adjustments. |
| `kind` | string | The transaction category: `call`, `tts`, `stt`, `flow_generation`, `transcription`, `number_rental`, `promotion` or `monthly_minimum`. **Branch on this**, never on `description`, and tolerate new categories. |
| `reference` | string | The id of the thing billed: the `tts_…` request id on a `tts` row (on a text-to-speech stream row, the socket's `session_id` and `#` the row's number); the `fgen_…` generation id, or the `ftr_…` transcription id, on a `flow_generation` row; the `trn_…` job id on a `transcription` row. |
| `quantity` | number | How much was billed: characters on an HTTP `tts` row (a stream row has none and carries `billed_seconds` and `per_min_inr` instead), tokens (input plus output) on a `flow_generation` row, seconds of audio (rounded up) on a `transcription` row. |
| `description` | string | Human-readable. Do not parse it. |
| `promotional_inr` | number | Promotional credit granted on a `promotion` row, or the portion of a debit paid with promotional credit. Omitted when zero. Promotional credit does not count towards a monthly minimum. |
| `pricing` | object | The rates snapshotted when the call was admitted: voice AI, optional T1 insights, and any managed provider rate and billing block. Absent on historical rows. |

The call amount combines voice and insights at the voice billing block, rounds
that charge up to a paisa, then adds the separately rounded provider charge.
BYO telco,
WhatsApp and browser calls have no Mirai telco component.

<Note>
**`kind`, `reference` and `quantity` are additive.** Rows written before they
existed carry no `kind` — read a missing `kind` as `call`. Nothing else about
the shape changed, so a reader that ignores all three keeps working.
</Note>

Reconcile against `call_id`: every billable call produces exactly one debit row.

### A text-to-speech row

[Speech requests](/v2/tts-quickstart#billing) over HTTP debit the same wallet,
at ₹1.80 per 1,000 characters, and only when the audio was delivered in full:

```json
{
  "id": "txn_01K4N7Q2R5S8T4V7W9X1Y3ZB6C",
  "object": "wallet_transaction",
  "type": "debit",
  "amount_inr": 0.12,
  "balance_after_inr": 494.88,
  "call_id": null,
  "kind": "tts",
  "reference": "tts_01K4N7Q0V8ZR3M6D9F2H5J7K1P",
  "quantity": 62,
  "description": "Text to speech · 62 characters · shruti",
  "created_at": "2026-09-09T09:16:39Z"
}
```

`reference` is the `X-Request-Id` the speech request returned, so a row
reconciles against your [request log](/v2/tts-quickstart#your-request-log) the
way a call row reconciles against `call_id`.

### A text-to-speech stream row

A [WebSocket stream](/v2/tts-websocket#billing) is billed for the time it is
open, ₹0.90 a minute. Each full minute is one row, charged when the minute
ends, and the last part-minute is one more row when the socket closes:

```json
{
  "id": "txn_01K8F2B4D6G8J0L2N4Q6S8U0W2",
  "object": "wallet_transaction",
  "type": "debit",
  "amount_inr": 0.9,
  "balance_after_inr": 493.98,
  "call_id": null,
  "kind": "tts",
  "reference": "ttsws_01K6Z8M3Q4R7T9V2X5Y8A1B4C7#1",
  "billed_seconds": 60,
  "per_min_inr": 0.9,
  "description": "Text to speech stream · 60 s · ₹0.90/min",
  "created_at": "2026-10-27T09:16:39Z"
}
```

`reference` is the socket's `session_id` from `session.ready`, then `#` and the
row's number on that socket, starting at 1. `billed_seconds` is the time the
row covers and `per_min_inr` the minute price the socket opened with. A stream
row has no `quantity`: the sentences on the socket are free, and each still
has its own row in your request log.

### A flow generation row

Each [AI flow draft](/v2/node-agents#what-a-draft-costs) is one debit, at the
provider's reported cost plus 20% (the chosen model's
[token rates](/general/tiers#ai-flow-drafts) when the provider reports none):

```json
{
  "id": "txn_01K8D5J7L9N1Q3S5U7W9Y1A3C5",
  "object": "wallet_transaction",
  "type": "debit",
  "amount_inr": 7.02,
  "balance_after_inr": 487.86,
  "call_id": null,
  "kind": "flow_generation",
  "reference": "fgen_01K8D5H2K4M6P8R0T2V4X6Z8B0",
  "quantity": 4532,
  "description": "Flow generation · claude-opus-5.5 · 1,512 in / 3,020 out tokens",
  "created_at": "2026-09-28T10:22:07Z"
}
```

`reference` is the `id` the generation returned, and `quantity` is its input
and output tokens together. A generation that failed or was interrupted is
charged the same way, and its description says so, for example
`Flow generation · gpt-6-sol · failed · 1,200 in / 2,400 out tokens`.

### A recording transcription row

Each [recording transcription](/v2/node-agents#what-transcription-costs) is one
debit of the same kind, at the provider's reported cost plus 20%:

```json
{
  "id": "txn_01K8E2G6J8L0N2Q4S6U8W0Y2A4",
  "object": "wallet_transaction",
  "type": "debit",
  "amount_inr": 1.95,
  "balance_after_inr": 485.91,
  "call_id": null,
  "kind": "flow_generation",
  "reference": "ftr_01K8E2F4H6K8M0P2R4T6V8X0Z2",
  "quantity": 4634,
  "description": "Recording transcription · gemini-3.8-flash · 1m41s · 2,717 in / 1,917 out tokens",
  "created_at": "2026-09-29T11:04:52Z"
}
```

`reference` is the `id` the transcription returned, and `quantity` is its input
and output tokens together; the description gives the recording's length. A
recording in which no conversation was heard is charged the same way, and its
description says so, for example
`Recording transcription · gemini-3.8-flash · failed · 12s · 410 in / 96 out tokens`.
Tell a transcription from a draft by its `reference` prefix, `ftr_` or `fgen_`.

### An offline transcription row

Each completed [offline transcription](/v2/transcribe-recorded-calls#pricing)
is one debit with `kind: "transcription"`, at ₹15 per hour of audio. Degraded
and failed jobs write no row.

```json
{
  "id": "txn_01M3XRSP44KR3116AZ578NC2F1",
  "object": "wallet_transaction",
  "type": "debit",
  "amount_inr": 0.1,
  "balance_after_inr": 8762.08,
  "call_id": null,
  "kind": "transcription",
  "reference": "trn_01M3XRSFXW77RHEQ85979AJXAF",
  "quantity": 24,
  "description": "Transcription · 23s of audio · mira-transcribe-offline-1",
  "created_at": "2026-10-02T07:38:26Z"
}
```

`reference` is the job's `id`, and `quantity` is the billed length in whole
seconds, rounded up. These rows are separate from the recording transcriptions
above, which turn calls into a flow and are billed as `flow_generation`.

## Top up

Once your company has gone live,
[add credit on Billing](https://console.voice.miraiminds.co/#/billing). The box
below covers a one-time pack and an unpaid month. A sandbox has its ₹200
starter credit; for more, [go live](/v2/go-live).

<OutOfCredit />

Credit is spent at your workspace's agreed rates. New T3 and T1 agreements
fund their monthly minimum upfront into this wallet. Paid usage counts towards
the minimum; any unused minimum is debited at the end of the billing month as a
`monthly_minimum` transaction. The minimum is not an extra fee on top of usage.
Top-ups above it remain available. Existing agreements retain their recorded
funding terms.

Promotional offers appear as `promotion` credits and are used before paid
credit. They do not replace upfront monthly funding or satisfy the minimum.
The **Billing** page shows your promotional balance, billing period and
minimum-spend progress.

A credit appears as a `credit` row and takes effect immediately. Your live
balance is always `GET /v2/wallet`, and on the **Developers** page of the
console. There is no top-up endpoint in the API.

## Low balance alerts

Subscribe an endpoint to `wallet.balance_low`, `wallet.depleted` and
`wallet.balance_restored` to hear when your balance drops below an alert level
you choose (₹500 by default), when a call or campaign is refused for balance,
and when you are back above the level. `payment.succeeded` and
`payment.failed` report top-ups and failed debits. See
[webhook subscriptions](/v2/webhook-subscriptions#wallet-and-payments).

These alerts watch your spendable balance, `balance_inr`, which leaves out
money held for renewals. With [renewal reserve](#wallet-settings) on, the
low-balance alert can fire earlier than it did, because each renewal is set
aside before its renewal day.

For a [sub-workspace with a spending limit](/v2/sub-workspaces#spending-limits),
`workspace.spend_limit.warning` and `workspace.spend_limit.reached` tell you
when the brand has used 80% and 100% of it. See
[spending limit events](/v2/webhook-subscriptions#spending-limits).

## `402` insufficient balance

Before dialling, we check the wallet can cover at least one minute at the
call's tier. If it cannot:

```json title="402 Payment Required"
{
  "error": {
    "code": "insufficient_balance",
    "message": "wallet balance 0.40 INR is below the minimum for one minute at t3"
  }
}
```

- **The gate runs pre-dial.** No phone rings, nothing is charged, no call object
  is created.
- **Retry after topping up**, with the same `Idempotency-Key` — the failed
  request did not consume it.
- **Calls already in flight are not killed.** Before a call dials, its
  worst-case charge is held (`held_for_calls_*`), so a call that started runs to
  its natural end and is then charged for the time it ran.

## `402` spend limit reached

A call placed with a [sub-workspace](/v2/sub-workspaces)'s header can also be
refused because that brand is at the
[spending limit](/v2/sub-workspaces#spending-limits) you set for it, even when
the wallet has credit:

```json title="402 Payment Required"
{
  "error": {
    "code": "spend_limit_reached",
    "message": "this sub-workspace has reached its spending limit",
    "doc_url": "https://docs.miraiminds.co/v2/sub-workspaces/#spending-limits",
    "spend_limit": { "object": "workspace_spend", "remaining_inr": 0, "state": "reached", "…": "…" }
  }
}
```

`error.spend_limit` is the brand's full [spend object](/v2/sub-workspaces#see-how-much-of-the-limit-is-used).
Nothing is dialled or charged. Topping up does not clear it: raise or remove the
brand's limit, or wait for the next month on a monthly limit.

## Handle a `402`

Handle both codes explicitly. They are business conditions rather than bugs:

<Tabs>
  <Tab title="Python">
    ```python
    r = httpx.post(f"{API}/v2/calls", headers=auth, json=payload, timeout=30)
    if r.status_code == 402:
        err = r.json()["error"]
        pause_campaign()
        if err["code"] == "spend_limit_reached":
            alert_ops(f"brand at its limit: {err['spend_limit']['remaining_inr']} INR left")
        else:  # insufficient_balance
            alert_ops(err["message"])
    else:
        r.raise_for_status()
    ```
  </Tab>
  <Tab title="Node.js">
    ```javascript
    const res = await fetch(`${API}/v2/calls`, { method: "POST", headers, body });
    if (res.status === 402) {
      const { error } = await res.json();
      await pauseCampaign();
      if (error.code === "spend_limit_reached") {
        await alertOps(`brand at its limit: ${error.spend_limit.remaining_inr} INR left`);
      } else { // insufficient_balance
        await alertOps(error.message);
      }
    } else if (!res.ok) {
      throw new Error(await res.text());
    }
    ```
  </Tab>
