A **call** is one outbound dial attempt driven by an [agent](/v2/agents).
Creating a call is asynchronous: you get `202 Accepted` immediately and the
outcome arrives by [webhook](/v2/webhooks) (or by polling
[`GET /v2/calls/{id}`](#get-a-call)). To show the call while it runs, open its
[live event stream](/v2/live-events).

A call can also run in your user's browser instead of on a phone: create it
with `channel: "web"`. See [Browser calls](/v2/web-calls) for the whole flow.

| Environment | Base URL |
| :--- | :--- |
| Sandbox | `https://sandbox.voice.miraiminds.co` |
| Production | `https://prod.voice.miraiminds.co`, once your company has [gone live](/v2/go-live) |

The examples on this page use the sandbox address. On the production address,
a key from a workspace that has not gone live is refused with
`403 production_workspace_required`.

## The call object

```json
{
  "id": "call_01K7Q9B4M8N3P6R2S5T7V9W1YA",
  "object": "call",
  "agent_id": "agt_01K7Q9F3K7M2N5P9R4T6V8W0XZ",
  "to": "+919876543210",
  "channel": "phone",
  "direction": "outbound",
  "status": "completed",
  "tier": "t3",
  "ended_reason": "customer-ended-call",
  "created_at": "2026-08-10T09:15:00Z",
  "started_at": "2026-08-10T09:15:02Z",
  "ended_at": "2026-08-10T09:16:38Z",
  "updated_at": "2026-08-10T09:17:41.208Z",
  "duration_secs": 96,
  "cost": {
    "amount_inr": 5,
    "per_min_inr": 3,
    "billing_block_secs": 10,
    "voice_per_min_inr": 3
  },
  "recording_available": true,
  "transcript_available": true,
  "transcript_status": "ready",
  "metadata": { "order_id": "8842" },
  "call_settings": {
    "voice_id": "neha",
    "language": "hi",
    "secondary_languages": ["en"],
    "sources": { "voice_id": "request", "language": "agent", "secondary_languages": "agent" }
  },
  "analysis": null,
  "outcome": null
}
```

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | string | `call_<ulid>`. Also the idempotency anchor and the workflow ID. |
| `agent_id` | string | The agent this call ran. |
| `to` | string | E.164 destination. On an incoming call, your number. |
| `from` | string | Phone calls only. The number the call rang from: your number or the shared line on a call you place, the caller's number on an incoming call. |
| `forwarded_from` | string | Incoming phone calls only. When a phone forwarded the call to your number (carrier call forwarding on busy, no answer, unreachable or always), the number of that phone in E.164, as the carrier reported it. Read on every kind of number: rented from Mirai, your own Plivo account and your own [SIP trunk](/v2/sip-trunk) (its `Diversion` or `History-Info` header). This is not the caller (`from`) and not your number (`to`). Absent when the call was not forwarded or the carrier did not send it. |
| `direction` | string | `outbound` for a call you or a campaign placed, `inbound` for a call to one of your numbers. On every call. Browser calls, text chats and realtime sessions are `outbound`. |
| `channel` | string | `phone`, `web` (a [browser call](/v2/web-calls)), `text` (a typed test chat from the console) or `realtime`. Calls placed before this field existed read as `phone`. |
| `status` | enum | See [statuses](#statuses). |
| `tier` | string | The rate card this call was billed under, which is your company's plan. See [tiers](/general/tiers). |
| `ended_reason` | string \| null | Why it ended. See [ended reasons](#ended-reasons). `null` while running. |
| `created_at` | string | RFC 3339, UTC. When we accepted the request. |
| `started_at` | string \| null | RFC 3339, UTC. Set when **media goes live**, not when we dialled. `null` if the call never connected. |
| `ended_at` | string \| null | RFC 3339, UTC. |
| `updated_at` | string | RFC 3339, UTC, with milliseconds. When anything this object holds last changed: the call ending, its transcript, analysis, post-call processing, recording, flow outcome or a human takeover. See [sync what changed](#sync-what-changed). |
| `duration_secs` | integer \| null | Billable seconds of live media. `0` for calls that never connected, `null` while running. |
| `cost.amount_inr` | number | Total rupees charged. `0` until the call is billed and for outcomes that are free. |
| `cost.per_min_inr` | number | The all-in per-minute rate this call is billed at. |
| `cost.billing_block_secs` | integer | The voice billing block in seconds: 10. |
| `cost.voice_per_min_inr` | number | Voice AI rate quoted for this call, when a pricing snapshot is available. |
| `cost.insights_per_min_inr` | number | T1 insights rate when enabled; absent when no insights charge applies. |
| `cost.telco_per_min_inr` | number | Managed provider rate; absent for BYO telco, WhatsApp and browser calls. |
| `cost.telco_provider` | string | The managed provider, when a provider charge applies. |
| `cost.telco_billing_block_secs` | integer | The provider's billing block, which can differ from the voice AI block. |
| `cost.ai_secs`, `cost.human_secs` | integer | Only on a call with a [human takeover](/v2/handoff): the seconds the agent handled and the seconds a person from your team handled. |
| `cost.human_per_min_inr`, `cost.human_per_min_paise` | number | Only on a call with a human takeover: the rate for the person's part, your plan's normal per-minute rate. |
| `cost.legs` | array | Only on a call where a person joined after a human takeover: one entry for each person, with `handoff_id`, `telco_secs`, `telco_per_min_inr`, `telco_per_min_paise`, `amount_inr` and `amount_paise` for their phone call. See [billing](/v2/handoff#billing). |
| `cost_inr` | number \| null | The same total as `cost.amount_inr`, kept for older integrations. `null` until the call is billed and on free calls. Use `cost.amount_inr` in new code. |
| `recording_available` | boolean | Whether [`GET /recording`](#get-the-recording) will return audio. |
| `transcript_available` | boolean | Whether [`GET /transcript`](#get-the-transcript) will return turns. |
| `transcript_status` | enum | `pending` while the call runs and until its transcript is stored; `ready` when [`GET /transcript`](#get-the-transcript) returns turns; `empty` when nobody spoke; `failed` when the transcript could not be stored. |
| `metadata` | object | Your [`metadata`](#metadata) from create, unchanged. For a campaign call, the contact's [`metadata`](/v2/campaigns#your-own-fields-metadata). Absent when the call has none. |
| `phone_number_id` | string | The [phone number](/v2/phone-numbers) the call rang from, when it came from one of your own. |
| `pool_id` | string | The [phone pool](/v2/phone-numbers) that picked the number. Only when a pool did, and then `calls_from_source` is `pool`. |
| `campaign_id` | string | The [campaign](/v2/campaigns) that placed the call. Only on campaign calls. |
| `contact_id` | string | The campaign contact the call was to: the `id` you sent with the contact, or the one we minted. Only on campaign calls. |
| `call_settings` | object | The voice and languages the call runs with, and who chose each. See [call settings](#call-settings). Absent on calls from before per-call settings existed (October 2026) and on incoming calls turned away before an agent was found. |
| `analysis` | object \| null | The [post-call analysis](/v2/analysis#where-the-result-appears) when the agent has `analysis.enabled`: summary, `success`, extracted `data` and, with templates, the chosen follow-up message in `analysis.template`. `null` otherwise. |
| `outcome` | string \| null | The name the post-call analysis chose from the agent's [`analysis.outcomes`](/v2/analysis#outcomes). See [outcome](#outcome). |
| `handling` | string | Only on a call with a [human takeover](/v2/handoff): `ai` while the agent has the call, `human` once a person from your team has joined. |
| `handoffs` | array | Only on a call with a human takeover: each takeover's `id`, `mode`, `connect`, `state`, `outcome`, `reason`, `created_at`, `joined_at`, `ended_at` and `duration_secs`. See [on the call](/v2/handoff#on-the-call). |
| `segments` | array | Only on a call where a person joined after a human takeover: who handled each part, as `handled_by` (`ai` or `human`), `start_ms`, `end_ms` and, on a person's part, `handoff_id`. |

### Outcome

`outcome` is the name the post-call analysis chose from the agent's
[`analysis.outcomes`](/v2/analysis#outcomes), such as `confirmed` or
`callback_requested`. The same value is in `analysis.outcome`.

It is `null` when the agent has no outcomes, when the analysis has not
finished or did not run, and when none of the outcomes fits.

It is on every call object: [`GET /v2/calls/{id}`](#get-a-call), each call in
[`GET /v2/calls`](#list-calls) and `data.call` in every
[webhook](/v2/webhooks). Events sent before the analysis (`call.queued`,
`call.started`, `call.completed` and the other endings) say `null`. Read the
outcome from `call.analysis.completed`, `call.processed` or
`GET /v2/calls/{id}`.

Filter the list by it: `GET /v2/calls?outcome=confirmed` keeps calls with that
outcome. Up to 20 comma-separated names match any of them
(`outcome=confirmed,cancelled`), and `outcome=null` keeps calls without one. It
combines with the other filters. [Call downloads](#download-your-calls) add an
`outcome` column after `summary` when the agent has outcomes.

This is separate from the console's call results (success, callback, talked,
not reached), which describe how any call went.

### Flow outcome

A call run by a [node-based agent](/v2/node-agents) also carries `flow`: where
the flow finished, the steps it went through and the values it extracted. It
appears here, on each call in [`GET /v2/calls`](#list-calls), and at
`data.call.flow` in [`call.processed`](/v2/webhooks#final-results). A call run by
a single-prompt agent has no `flow` field.

```json
{
  "flow": {
    "final_node": "goodbye",
    "nodes_visited": ["Confirm the customer", "Offer the delivery slot", "Close"],
    "variables": { "identity_confirmed": true, "slot_accepted": true },
    "status": "end_call",
    "tags": ["end_call"]
  }
}
```

| Field | Description |
| :--- | :--- |
| `final_node` | The `id` of the node the call ended on. Omitted when unknown. |
| `nodes_visited` | The `name` of each node the call entered, in the order it first entered them. Always present; `[]` when none. |
| `variables` | Every extracted value, by variable name. Always present; `{}` when none. |
| `status` | How the flow ended: `end_call`, `user_hangup`, `user_idle_max_duration_exceeded`, `call_duration_exceeded`, `voicemail_detected`, `pipeline_error` or `system_cancelled`. Omitted when unknown. See [reading the outcome](/v2/node-agents#step-6-read-the-outcome). |
| `tags` | Labels recorded for the call, such as how it ended. Omitted when unknown. |

`flow` is absent until the outcome is recorded, usually within seconds of the
call ending, so it can be missing from the terminal event. `call.processed`
waits up to 2 minutes for it.

{/* /FLOW-OUTCOME */}

## Statuses

| Status | Terminal | Meaning |
| :--- | :---: | :--- |
| `queued` | | Accepted, waiting on fleet capacity. A [browser call](/v2/web-calls) stays here until the page connects its audio. |
| `dialing` | | SIP invite sent, phone is ringing. Phone calls only. |
| `in_progress` | | Media live, conversation running. |
| `completed` | ✅ | Connected and finished normally. **Billable.** |
| `voicemail` | ✅ | An answering machine picked up. See [voicemail](/v2/agents#voicemail). **Billable.** |
| `no_answer` | ✅ | Rang out, nobody picked up. Free. |
| `busy` | ✅ | Callee's line was busy. Free. |
| `failed` | ✅ | Could not connect, or the pipeline errored. Free. |
| `timeout` | ✅ | Hit `max_duration_secs`. **Billable.** |
| `aborted` | ✅ | You cancelled it with [`POST /abort`](#abort-a-call) while it was queued, ringing or mid-conversation. Free in every case. |

Statuses only move forward. A terminal status never changes.

```mermaid
stateDiagram-v2
    [*] --> queued: POST /v2/calls
    queued --> dialing: capacity acquired
    queued --> aborted: POST /abort
    dialing --> aborted: POST /abort
    in_progress --> aborted: POST /abort
    dialing --> in_progress: media live
    dialing --> no_answer
    dialing --> busy
    dialing --> failed
    dialing --> voicemail: machine detected
    in_progress --> completed
    in_progress --> voicemail
    in_progress --> timeout: max_duration_secs
    in_progress --> failed
    completed --> [*]
    voicemail --> [*]
    no_answer --> [*]
    busy --> [*]
    failed --> [*]
    timeout --> [*]
    aborted --> [*]
```

## Ended reasons

`ended_reason` explains *why* a terminal status was reached. Match on `status`
for control flow; use `ended_reason` for analytics and support.

| `ended_reason` | Usual `status` | Meaning |
| :--- | :--- | :--- |
| `assistant-ended-call` | `completed` | The agent called `end_call` because its job was done. |
| `customer-ended-call` | `completed` | The callee hung up. |
| `exceeded-max-duration` | `timeout` | Hit `max_duration_secs`. |
| `customer-did-not-answer` | `no_answer` | Rang out. |
| `customer-busy` | `busy` | Line busy. |
| `voicemail` | `voicemail` | An answering machine answered. Detecting the machine is what sets the status, so this reason and that status always appear together. |
| `silence-timed-out` | `completed` | Media was live but nobody spoke for the silence timeout: nobody ever spoke, or the agent's `silence_hang_up` is off and the line stayed quiet after its last check-in. Billable, because the agent ran. |
| `idle-timed-out` | `completed` | The caller went quiet. The agent checked in (by default once, after about 10 seconds), then said goodbye. See [When the caller goes quiet](/v2/agents#when-the-caller-goes-quiet). Billable. |
| `no-media` | `failed` | The call was placed but its audio never arrived. An incoming caller who hung up before we answered, and a call to a number whose connection is switched off, also end this way. See the note below. Not billed. |
| `insufficient_balance` | `failed` | Your wallet couldn't pay for the call when we set it up, so it never started. An incoming caller is not answered. It has an underscore, the same spelling as the [`402 insufficient_balance`](/v2/wallet#402-insufficient-balance) that `POST /v2/calls` answers with. Not billed. |
| `spend_limit_reached` | `failed` | The call's [sub-workspace](/v2/sub-workspaces) is at its [spending limit](/v2/sub-workspaces#spending-limits): what is left of the limit couldn't hold the call's worst case, or for an incoming call couldn't cover one minute, so it never started. An incoming caller is not answered. Not billed. |
| `agent-unavailable` | `failed` | An incoming call that no agent could take. The number has no agent, or its agent is missing, a draft or archived, runs a flow your plan's model can't run, or needs an input an incoming call can't supply. A WhatsApp number or integration that is switched off ends this way too. The caller is not answered. Not billed. |
| `setup-timeout` | `failed` | An incoming call we couldn't get ready before the caller's ring ran out. Not billed. |
| `skipped-by-condition` | `aborted` | A pre-call [`skip_call`](/v2/tools#skip-when-a-condition-holds) matched, or your [WhatsApp resolver](/cookbooks/whatsapp-calling-for-partners) answered `allow: false`. Nothing was dialled, and an incoming caller is not answered. Free. |
| `precall-tool-failed` | `failed` | A pre-call tool with `on_failure: "abort"` failed or ran out of time. Nothing was dialled, and an incoming caller is not answered. Free. |
| `aborted-by-api` | `aborted` | You called [`POST /abort`](#abort-a-call). An abort produces this reason and no other. |
| `api-ended-call` | `completed` | You sent a [`close` control](/v2/live-control): the agent said goodbye and the call ended. Billable. |
| `time-limit-close` | `completed` | The [timing policy](/v2/web-calls#timing-policy) closed the call before its hard cap. Billable. |
| `user-silence-close` | `completed` | The [timing policy](/v2/web-calls#timing-policy) closed the call after the user stayed silent for `user_silence_close_secs`. Billable. |
| `assistant-error` | `failed` | A failure on our side, while setting the call up or during it. Not billed. |
| `transferred` | `completed` | The call ended while a person from your team was on it after a [human takeover](/v2/handoff): the person or the caller hung up, or you ended it with `end`. Billable. |
| `balance-exhausted` | `completed` | Reserved for a call ended when the wallet emptied mid-call. **Not wired, so no call emits this yet.** |

<Note>
Treat `ended_reason` as an open vocabulary. We add new values without a version
bump, so always have a default branch. The last row above is in the
vocabulary, but **no call emits it today**. It arrives with a later release.
See the [roadmap](/general/roadmap).
</Note>

<Warning>
**`no_answer` is under-reported today**

Some calls that genuinely rang out are reported as `failed` with
`ended_reason: "no-media"` rather than as `no_answer`.

Whether we can tell the two apart depends on what the carrier tells us. When the
carrier returns a clear verdict (SIP 480 or 408 for rang out, 486 or 600 for
busy), you get `no_answer` or `busy` correctly. When it black-holes the call
instead, accepting the invite and returning nothing, we have no signal to tell
"rang, nobody picked up" apart from "answered into silence". The call then ends
as `failed` with `no-media` after the media gate expires.

If you count unanswered calls for retry logic, treat `no_answer`, `busy`, and
`failed` with `no-media` together as calls that did not connect. None of the
three is billed, so your costs are unaffected either way. We are working on
this, and the reported status will only get more specific over time.
</Warning>

## Create a call

```http
POST /v2/calls
```

### Request

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `agent_id` | string | yes | The agent to run. |
| `channel` | string | no | `phone` (default) or `web`. `web` runs the call in a browser. See [Browser calls](/v2/web-calls). |
| `to` | string | phone only | E.164, e.g. `+919876543210`. Required for phone calls. Refused with `400 invalid_request` on `channel: "web"`. |
| `variables` | object | no | Flat string map substituted into the agent's prompt. See [variables](#variables). |
| `metadata` | object | no | Your own identifiers, up to 16 string keys and values. Returned unchanged on the call and in every webhook. Never shown to the agent. See [metadata](#metadata). |
| `first_message` | string | no | The opening line for this call only, up to 500 characters. Replaces the agent's `first_message`; `{{variable}}` placeholders work the same way. Refused for a [node-based agent](/v2/node-agents), whose start node opens the call. |
| `system_prompt` | string | no | The agent's instructions for this call only, 1 to 16,000 characters. Replaces the agent's `system_prompt`; `{{variable}}` placeholders are filled from `variables`. Refused on `channel: "realtime"` and for a [node-based agent](/v2/node-agents). Never returned on the call or in webhooks. See [per-call prompt](#per-call-prompt). |
| `call_settings` | object | no | The voice and languages for this call only: `voice_id`, `language` and `secondary_languages`. The agent is not changed. See [call settings](#call-settings). |
| `webhook_url` | string | no | HTTPS URL for [lifecycle events](/v2/webhooks). Applies to this call only. Signed with your API key's Call webhook secret, or with a destination's secret when the URL is also a [destination](/v2/webhook-subscriptions). See [which webhook secret to use](/v2/webhook-secrets). |
| `phone_number_id` / `pool_id` | string | no | Phone calls only. Ring from one of your own [phone numbers](/v2/phone-numbers), or from the number a pool picks. Without either, the call uses the agent's `calls_from`, then your default pool, then your own number, and the Mirai shared line only when your workspace has no number that can place calls. See [which number a call comes from](/v2/phone-numbers#which-number-a-call-comes-from). Send one, not both. |
| `max_duration_secs` | integer | no | Overrides the agent's cap for this call only. |
| `timing` | object | no | Wrap-up, timed-close and user-silence timers for this call. Phone and browser calls. See [timing policy](/v2/web-calls#timing-policy). |
| `recording_enabled` | boolean | no | Default `true`. `false` stores no audio for this call: no recording, `recording_available: false`. If your workspace has recording turned off, the default is `false` and `true` is refused with `403 recording_disabled`. |
| `final_results` | boolean | no | Default `false`. `true` sends one [`call.processed`](/v2/webhooks#final-results) with the finished transcript after the call ends. |
| `tier` | string | no | `t1` \| `t3` \| `t5`. Defaults to your key's tier, which is your company's plan, so leave it out. Any other tier is refused with `403 contract_unavailable`. Before your company goes live, every call runs at `t5`, whatever you send. See [tiers](/general/tiers#setting-the-tier). |

```json title="202 Accepted"
{
  "id": "call_01JZQ9B4M8N3P6R2S5T7V9W1YA",
  "status": "queued",
  "events_url": "https://sandbox.voice.miraiminds.co/v2/calls/call_01JZQ9B4M8N3P6R2S5T7V9W1YA/events?token=…"
}
```

`202` means the call is admitted to the queue. **The phone has not rung yet.**
The full call object is available from [`GET /v2/calls/{id}`](#get-a-call).

| Field | Description |
| :--- | :--- |
| `id` | The call ID. It is the `data.call.id` of every webhook for this call. |
| `status` | `queued`. |
| `events_url` | The call's [live event stream](/v2/live-events): the agent's state and each turn while the call runs. It carries its own read-only token, valid for the call's maximum duration plus one hour, so you can hand it to a browser without your API key. |

A phone call's `202` has no `ws_url` and no `transport`. A browser call's `202`
adds them, because the page also needs an audio link:

```json title="202 Accepted (channel web)"
{
  "id": "call_01K8B2M4Q6S8T0V2X4Z6A8C0EG",
  "status": "queued",
  "transport": "web",
  "ws_url": "wss://sandbox.voice.miraiminds.co/v2/calls/call_01K8B2M4Q6S8T0V2X4Z6A8C0EG/media?token=…",
  "ws_url_expires_at": "2026-09-27T10:05:00Z",
  "events_url": "https://sandbox.voice.miraiminds.co/v2/calls/call_01K8B2M4Q6S8T0V2X4Z6A8C0EG/events?token=…"
}
```

| Field | Description |
| :--- | :--- |
| `transport` | `web`. |
| `ws_url` | The [audio socket](/v2/web-calls#audio-socket). Single use; connect within 5 minutes. |
| `ws_url_expires_at` | When an unused `ws_url` stops working. |
| `events_url` | The [live event stream](/v2/live-events). Reusable for the call and for one hour after it ends. |

### Errors

| Status | `error.code` | Cause |
| :--- | :--- | :--- |
| `400` | `invalid_request` | Missing `agent_id`/`to`, `to` not E.164, `to` sent with `channel: "web"`, `max_duration_secs` out of range, invalid `metadata`, `first_message`, `system_prompt`, `timing` or [`call_settings`](#call-settings), or `system_prompt` sent with `channel: "realtime"`. `error.message` names the field. |
| `401` | `unauthorized` | Bad or missing key |
| `402` | `insufficient_balance` | Wallet cannot cover the first minute at your tier. We check before we dial, so there is no partial charge. See [Wallet](/v2/wallet#402-insufficient-balance). |
| `402` | `spend_limit_reached` | Sent with a sub-workspace's header when that brand's remaining [spending limit](/v2/sub-workspaces#spending-limits) can't cover one minute of the call. Nothing is dialled or charged. |
| `403` | `recording_disabled` | `recording_enabled: true` on a workspace whose recording is turned off |
| `403` | `contract_unavailable` | The call is not covered by an active production contract: `tier` is not your company's plan, or the company has not finished going live. See [setting the tier](/general/tiers#setting-the-tier). |
| `404` | `not_found` | `agent_id` does not exist in your workspace (including one that exists in someone else's) |
| `409` | `duplicate_call` | A request with this `Idempotency-Key` is still being processed. See [idempotency](#idempotency). |
| `409` | `number_retired`, `number_resting`, `pool_busy`, `pool_unavailable` | The number or pool you chose cannot place the call right now. Nothing was dialled and no other number was used. `pool_busy` carries `Retry-After`. See [phone numbers and pools](/v2/phone-numbers#errors). |
| `400` | `invalid_flow` | `agent_id` is a [node-based agent](/v2/node-agents) and your tier's model cannot run flows. The body lists the problem with its path. Nothing was dialled. |
| `409` | `flow_agent_voice_only` | A text chat (`channel: "text"`) with a node-based agent. Node-based agents run on `phone` and `web`. |
| `409` | `flow_first_message_unsupported` | `first_message` sent for a node-based agent. Its start node's `greeting` opens the call; personalise it with `variables`. |
| `409` | `flow_system_prompt_unsupported` | `system_prompt` sent for a node-based agent. Its nodes' prompts run the call; personalise them with `variables`. |
| `422` | `do_not_call` | `to` is on your [do-not-call list](/v2/dnc). Nothing was reserved, dialled or charged. See [do-not-call is always on](#do-not-call-is-always-on). |
| `429` | `rate_limited` | Request rate exceeded, or your queue is full (500 calls accepted and not yet ended); `error.message` says which. Going over your concurrency cap does not return 429: those calls wait in the queue. Honour `Retry-After`. See [Limits](/v2/limits). |
| `429` | `at_capacity` | Every line on the deployment is busy. `Retry-After: 30`. Nothing was charged. |
| `501` | `tier_unavailable` | `tier` names a tier that is not enabled on this deployment |

### Do-not-call is always on

A phone call to a number on your [do-not-call list](/v2/dnc) is refused with
`422 do_not_call` before anything is reserved. That covers a number you added,
a person who asked on an earlier call not to be called again, and a person who
filed a TRAI complaint about an unwanted call. It cannot be turned off.
`error.message` says which applies.

`POST /v2/calls` rings as soon as it can and has no calling hours of its own.
For calling hours, a not-before time, an expiry or a priority, add the person
as a contact to an [always-on campaign](/v2/campaigns#contact-schedule)
instead.

### Variables

`variables` is a flat map of string keys to string values. Each key replaces the
matching `{{key}}` placeholder in the agent's `system_prompt` and
`first_message`, or in the call's own `system_prompt` and `first_message` when
you send them.

```json
{ "variables": { "customer_name": "Rahul", "order_id": "8842" } }
```

- Plain `{{key}}` placeholders match loosely: letters and digits only,
  case-insensitive, so `{{Customer Name}}`, `{{customer_name}}` and
  `{{CustomerName}}` all read the same variable. Only a Liquid expression
  with a filter (`{{ key | upcase }}`) needs the exact key.
- A placeholder with no matching variable is replaced with an empty string.
  There is no error, and no `{{braces}}` are left for the agent to read aloud.
  Validate on your side.
- Keep values short. They are part of the prompt, and the prompt is on the
  latency path.
- Variables are **static per call**. There is no way to change them mid-call.
  An [`instruction`](/v2/live-control) can direct the agent mid-call instead.
- On a [node-based agent](/v2/node-agents#variables-in-node-text), variables
  fill the node prompts, the start node's greeting and extraction prompts.
  Transition conditions are not filled in.

#### Time and weekday

Two placeholders are filled by us when the call starts, in the prompt, the
first message, the end-call and voicemail messages and the call-timing
messages. They need no `variables` and no `input_schema` entry.

| Placeholder | Becomes |
| :--- | :--- |
| `{{current_time_Asia/Kolkata}}` | The time in that IANA zone, such as `2026-11-22 14:30:05 IST`. |
| `{{current_weekday_Asia/Kolkata}}` | The weekday in that zone, such as `Sunday`. |

- Without a zone (`{{current_time}}`) the call's own timezone is used: India's,
  unless a [campaign](/v2/campaigns) sets another.
- The value is the clock when the call starts, so an agent can turn "call me
  in two hours" into a time. It already knows today's date without them.
- Put them near the end of the prompt. A prompt whose opening is the same on
  every call starts answering faster.
- A variable you send with the same name wins over the clock.
- [Post-call analysis](/v2/analysis) is told the call's date and time on its
  own, so a field such as `callback_at` resolves "in two hours" without them.

### Per-call prompt

`system_prompt` on the call replaces the agent's prompt for that call only. The
agent is not changed, and the rest of its setup still applies to the call: its
voice, language, opening line and tools.

One agent with `variables` is still the simplest way to personalise calls,
because the instructions stay the same and only the details change. Send a
per-call prompt when each call needs different instructions, for example when
your own system writes the script for each customer.

```bash
curl -X POST https://sandbox.voice.miraiminds.co/v2/calls \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-8842-redelivery-1" \
  -d '{
    "agent_id": "agt_01JZQ8F3K7M2N5P9R4T6V8W0XZ",
    "to": "+919876543210",
    "system_prompt": "You are Priya from Acme. {{customer_name}} missed the delivery of order {{order_id}} yesterday. Apologise once, offer a new slot tomorrow between 10:00 and 18:00, and confirm the delivery address. Keep replies to one or two short sentences. When the customer is done, thank them and end the call.",
    "variables": { "customer_name": "Rahul", "order_id": "8842" },
    "webhook_url": "https://example.com/mirai/webhook"
  }'
```

- It holds 1 to 16,000 characters, the same ceiling as the agent's prompt. A
  blank or longer prompt returns `400 invalid_request`.
- `{{variable}}` placeholders are filled from the call's `variables`, as they
  are in the agent's prompt, and checked by the same rule. If the agent
  declares an `input_schema`, every variable the prompt reads must be declared
  in it. An undeclared one returns `400 invalid_request`.
- It works on `phone` and `web` calls. A `realtime` session takes its
  instructions from the client's `session.update`, so `system_prompt` on
  `channel: "realtime"` returns `400 invalid_request`.
- A [node-based agent](/v2/node-agents) runs its nodes' prompts, so it refuses
  a per-call prompt with `409 flow_system_prompt_unsupported`.
- We never return it: it is not on the [call object](#the-call-object) and not
  in any [webhook](/v2/webhooks). To know later which prompt a call ran, store
  it on your side against the call `id`.
- Keep it short. The prompt is on the latency path, and a long one adds delay
  well before it reaches the limit. See the
  [prompting guide](/v2/prompting-guide).

### Call settings

`call_settings` sets the voice and the languages of one call. The agent and its
saved revisions stay as they are.

```bash
curl -X POST https://sandbox.voice.miraiminds.co/v2/calls \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-8842-confirm-gu-1" \
  -d '{
    "agent_id": "agt_01JZQ8F3K7M2N5P9R4T6V8W0XZ",
    "to": "+919876543210",
    "variables": { "customer_name": "Mehul", "order_id": "8842" },
    "call_settings": { "voice_id": "sameer", "language": "gu", "secondary_languages": ["en"] }
  }'
```

| Key | Description |
| :--- | :--- |
| `voice_id` | The voice the agent speaks in. It takes the same values as an agent's `voice.voice_id`: `ashu`, `neha`, `shruti`, `sameer`, `munshi` or `tanvi`. See [Voices](/v2/voices). |
| `language` | The call's main language, written the way an agent's `language` is (`hi`, `gu`, `en-IN`), up to 35 characters. Speech recognition listens for it. |
| `secondary_languages` | Other languages the caller may speak. Up to 4 of `hi`, `en`, `gu`, `mr`, `bn`, `ta`, `te`, `kn`, `ml`, `pa` and `od`. A regional tag is read as its base code (`gu-IN` is `gu`), and duplicates and the main language are dropped. `[]` listens for the main language only. |

Every key is optional. A key you leave out keeps the agent's value. The
settings apply from the agent's first word, greeting included, on phone and
browser calls. A [Realtime session](/v2/realtime) takes no `call_settings`: it
starts from its agent's voice and languages, and the client's `session.update`
sets its own (see [Realtime languages](/v2/realtime#languages)).

`language` sets what speech recognition listens for, and our standby voice
pronounces in it if it serves the call. It does not change your prompt. If the
agent should reply in that language, say so in the prompt, for example with a
[variable](#variables).

The older `"voice": { "voice_id": "…" }` on a request still works and means
`call_settings.voice_id`. Send one or the other: both with different values is
a `400`.

#### Where the settings come from

`call_settings` is accepted in three places, with the same keys and rules. A
call starts from the agent's own values, and each later source wins, key by
key:

| Order | Source | Where you set it | In `sources` |
| :---: | :--- | :--- | :--- |
| 1 | The agent | `voice.voice_id`, `language` and `secondary_languages` on the [agent](/v2/agents) | `agent` |
| 2 | Your request | `call_settings` on `POST /v2/calls` | `request` |
| 3 | A campaign contact | `call_settings` on the [contact](/v2/campaigns#voice-and-language-per-contact) | `campaign` |
| 4 | Pre-call tools, in the order they run | A `call_settings` object in the [tool's result](/v2/tools#set-the-voice-and-language-for-the-call) | `pre_call:<tool name>` |

A request can set the voice, for example, and a pre-call tool that answers
with only `language` then changes the language and keeps the request's voice.

#### Bad values

On a request, a bad value is `400 invalid_request` and nothing is dialled. The
message names the key and, where there is a fixed list, the values allowed:

```json title="400 Bad Request"
{
  "error": {
    "code": "invalid_request",
    "message": "call_settings.voice_id \"priya\" is not a voice; it must be one of ashu, munshi, neha, sameer, shruti, tanvi"
  }
}
```

The same `400` answers a value of the wrong type, a blank value (leave the key
out instead), an unknown key, a `language` longer than 35 characters, a
secondary language outside the list, and more than 4 secondary languages.

A campaign contact with a bad value is rejected on its own row, and the rest
of the list goes in. A pre-call tool's bad value never fails the call: the call
keeps the value it had, and the tool's receipt says which key was skipped and
why.

#### On the call object

Every call shows the settings it runs with, the agent's own values included,
and who chose each one. They are on [`GET /v2/calls/{id}`](#get-a-call), on
each call in [`GET /v2/calls`](#list-calls) and in `data.call` of every
[webhook](/v2/webhooks).

```json
{
  "call_settings": {
    "voice_id": "sameer",
    "language": "gu",
    "secondary_languages": ["en"],
    "sources": {
      "voice_id": "pre_call:user_lookup",
      "language": "pre_call:user_lookup",
      "secondary_languages": "agent"
    }
  }
}
```

Each value in `sources` is `agent`, `request`, `campaign` or
`pre_call:<tool name>`. `call.queued` shows the settings before pre-call tools
run, and every event from `call.started` on shows the ones the call used.

Calls from before per-call settings existed have no `call_settings`, and
neither does an incoming call turned away before an agent was found.

### Metadata

`metadata` holds your own identifiers, so every webhook can be matched to your
records without a lookup table:

```json
{ "metadata": { "session_id": "sess_8f2c41", "user_id": "usr_1042" } }
```

- Up to 16 keys. A key is 1 to 40 characters: ASCII letters, digits and `_`, `.`,
  `:`, `-`, starting with a letter, digit or `_`.
- Values are strings of up to 256 characters. The whole object, serialized, is
  at most 4 KB.
- It is fixed when the call is created and returned unchanged on the
  [call object](#the-call-object) and in `data.call` of every
  [webhook](/v2/webhooks) for the call.
- The agent never sees it. Anything the agent should use goes in
  [`variables`](#variables).
- Your [tools](/v2/tools#verify-a-tool-request) get it too: every tool request
  carries it in the `X-Mirai-Call-Metadata` header, and a tool's URL, headers,
  query and body can read `{{ call.metadata.<key> }}`.
- A call without metadata has no `metadata` field at all.
- Put IDs in it, not secrets or personal data: it travels on every webhook.

Invalid or oversized metadata returns `400 invalid_request`.

### Idempotency

Send `Idempotency-Key` with a value derived from your own domain object:

```bash
-H "Idempotency-Key: order-8842-confirm-1"
```

If we have seen that key in the last 24 hours, we replay the original response
byte for byte and place **no second call**. This is the safe way to retry a
request that timed out. A network timeout does not tell you whether the call was
placed, and without the key a retry makes the customer's phone ring twice.

The replay repeats `events_url` while its token is valid, and leaves it out
after that. Your API key still opens the [live event stream](/v2/live-events).

The key is scoped to your workspace. Reusing a key with a *different* body still
replays the original response, so pick keys that are unique per intended call.

There is one window where a reused key does not replay: while the **first**
request with that key is still being processed, there is no stored response to
replay yet, so the second request gets
[`409 duplicate_call`](/v2/errors#error-codes). It means the first request is
already in flight and no second call was placed. Retry a moment later to get the
original response, or wait for the webhook.

## Get a call

```http
GET /v2/calls/{id}
```

<Tabs>
  <Tab title="cURL">
    ```bash
    curl https://sandbox.voice.miraiminds.co/v2/calls/call_01JZQ9B4M8N3P6R2S5T7V9W1YA \
      -H "Authorization: Bearer sk_live_YOUR_API_KEY"
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import time

    TERMINAL = {"completed", "voicemail", "no_answer", "busy", "failed", "timeout", "aborted"}

    def wait_for_call(call_id: str, timeout_secs: int = 600) -> dict:
        """Prefer webhooks. Poll only when you cannot host an endpoint."""
        deadline = time.monotonic() + timeout_secs
        while time.monotonic() < deadline:
            call = httpx.get(f"{API}/v2/calls/{call_id}", headers=auth, timeout=30) \
                        .raise_for_status().json()
            if call["status"] in TERMINAL:
                return call
            time.sleep(5)
        raise TimeoutError(call_id)
    ```
  </Tab>
  <Tab title="Node.js">
    ```javascript
    const TERMINAL = new Set([
      "completed", "voicemail", "no_answer", "busy", "failed", "timeout", "aborted",
    ]);

    async function waitForCall(callId, timeoutMs = 600_000) {
      const deadline = Date.now() + timeoutMs;
      while (Date.now() < deadline) {
        const call = await fetch(`${API}/v2/calls/${callId}`, { headers: auth })
          .then((r) => r.json());
        if (TERMINAL.has(call.status)) return call;
        await new Promise((r) => setTimeout(r, 5000));
      }
      throw new Error(`timed out waiting for ${callId}`);
    }
    ```
  </Tab>
</Tabs>

**`200 OK`** returns the [call object](#the-call-object). You get
**`404 not_found`** both for an unknown ID and for an ID that belongs to another
workspace. The two responses are identical on purpose.

<Tip>
Poll no faster than every 5 seconds, and only when you cannot receive webhooks.
Polling counts against your [rate limit](/v2/limits); webhooks do not.
</Tip>

```http
GET /v2/calls/{id}/transcript
```

Returns what was said, as turns, once the call has ended.

```bash
curl https://sandbox.voice.miraiminds.co/v2/calls/call_01K7Q9B4M8N3P6R2S5T7V9W1YA/transcript \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY"
```

```json title="200 OK"
{
  "call_id": "call_01K7Q9B4M8N3P6R2S5T7V9W1YA",
  "turns": [
    {
      "role": "assistant",
      "text": "नमस्ते Rohit जी, मैं Acme Retail से Priya बोल रही हूँ। एक मिनट बात कर सकती हूँ?",
      "start_ms": 420,
      "end_ms": 4980
    },
    { "role": "user", "text": "हाँ बोलिए", "start_ms": 5640, "end_ms": 6390 },

      "role": "assistant",
      "text": "आपका order AC-88213 kal shaam 6 baje deliver hoga. Ye slot theek hai?",

      "end_ms": 14880
    },
    { "role": "user", "text": "haan theek hai", "start_ms": 15900, "end_ms": 17240 }

```

| Field | Notes |
| :--- | :--- |

```json title="404 Not Found"
{
  "error": {
    "code": "not_found",
    "message": "transcript not available (call still in progress or produced no speech)"
  }
}
```

## Get the recording

```http
GET /v2/calls/{id}/recording
```

Returns `302` to a signed, time-limited URL for the call's audio (WAV). Follow
the redirect. Most HTTP clients do by default; `curl` needs `-L`.

```bash
curl -L https://sandbox.voice.miraiminds.co/v2/calls/call_01K7Q9B4M8N3P6R2S5T7V9W1YA/recording \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  -o call.wav
```

```http title="302 Found"
Location: https://storage.miraiminds.co/voice-agents/production/call_records/call_01K7Q9B4M8N3P6R2S5T7V9W1YA/call.wav?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Expires=900&X-Amz-Signature=…
```

<Warning>
**The signed link expires in 15 minutes and it is a bearer token.**

Use it to fetch the recording right away. To get the audio later, store the
`call_id` and ask again; do not store the link. Anyone holding it can fetch the
audio until it expires, so treat it exactly as you would treat the recording.
</Warning>

`404 not_found` while the call is running, for a call that produced no audio, and
for one whose audio was never stored, which includes every call created with
`recording_enabled: false`. `recording_available` on the call object tells you
which requests are worth making.

Transcripts and recordings are kept with **no expiry** today, the same as the
call record. Workspace retention settings, and APIs to delete call data, are
coming in an upcoming release; we'll let you know when they ship. See
[data retention](/v2/limits#data-retention).

## Abort a call

```http
POST /v2/calls/{id}/abort
```

Cancels a call that has not ended yet. Abort is accepted while the call is
`queued`, `dialing` or `in_progress`. If the call is live, the SIP server hangs
it up mid-conversation. On a [browser call](/v2/web-calls), abort also closes
the browser's audio socket. Only a call that has already reached a terminal
status is refused.

Abort is immediate and silent. To end a call with a spoken goodbye, send a
[`close` control](/v2/live-control) instead.

```bash
curl -X POST https://sandbox.voice.miraiminds.co/v2/calls/call_01JZQ9B4M8N3P6R2S5T7V9W1YA/abort \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY"
```

```json title="202 Accepted"
{ "id": "call_01JZQ9B4M8N3P6R2S5T7V9W1YA", "status": "aborted" }
```

`202` means the cancel was signalled. The call reaches `aborted` shortly after
with `ended_reason: "aborted-by-api"`, and a
[`call.aborted`](/v2/webhooks#call-aborted) event fires. An aborted call is billed for
the time it was connected, at the same rate and in the same blocks as any other
call. An abort while the call is still queued or ringing costs nothing.

| Status | `error.code` | Cause |
| :--- | :--- | :--- |
| `404` | `not_found` | Unknown call ID, or a call in another workspace |
| `409` | `conflict` | The call has already ended (its status is terminal), so there is nothing to abort |

## Live control and events

Three more endpoints work while a call runs. Every voice call has the live
event stream and takes live controls: phone calls you place, campaign and
inbound calls, browser calls and realtime sessions.
[Live control](/v2/live-control) covers controls in full.

| Endpoint | What it does |
| :--- | :--- |
| `GET /v2/calls/{id}/events` | The live event stream (Server-Sent Events): agent state, each completed turn and, for a [node-based agent](/v2/node-agents), each step. Every call has one: phone calls you place, campaign and inbound calls, browser calls and realtime sessions. Opened with the `events_url` from create, or with your API key. See [Live events](/v2/live-events). |
| `POST /v2/calls/{id}/control` | Send an `instruction` the agent follows from its next reply, a line it says word for word (`say`), an audio clip to play (`play`), or `close` the call with a spoken goodbye. Any voice call in progress. See [Live control](/v2/live-control). |
| `GET /v2/calls/{id}/control/{control_id}` | Read a control's current status: `pending`, `applied`, `rejected` or `failed`. |

| Status | `error.code` | Cause |
| :--- | :--- | :--- |
| `400` | `invalid_request` | A control body that does not fit its `type`, or a clip that is not audio, is over 2 MB or over 60 seconds |
| `400` | `audio_unavailable` | A `play` control's `audio_url` could not be fetched |
| `400` | `unsupported_channel` | Control sent to a console text chat |
| `401` | `invalid_token` | The `token` in a media or events link is unknown, expired, already used, or for another call |
| `404` | `not_found` | Unknown call or control ID, or one in another workspace |
| `409` | `call_not_active` | Control sent to a call that has not connected yet (still ringing or `queued`) or has already ended |

To have a person from your team join a phone call and take it over from the
agent, see [Human takeover](/v2/handoff). It has its own endpoints under
`/v2/calls/{id}/handoffs`.

## List calls

```http
GET /v2/calls
```

Your calls, newest created first, inbound and outbound together. Each item is
the same [call object](#the-call-object) that
[`GET /v2/calls/{id}`](#get-a-call) returns.

The list has no row cap and no time cut-off. It holds your newest 100,000
calls; read an older call by its id. For a bulk file, use
[`GET /v2/calls/export`](#download-your-calls): CSV or JSON lines, up to 31
days and 100,000 calls per file.

| Query param | Description |
| :--- | :--- |
| `limit` | 1–100, default 20. |
| `cursor` | `next_cursor` from the previous page. Send the same filters with it. |
| `from` | RFC 3339. Calls created **at or after** this instant (inclusive). |
| `to` | RFC 3339. Calls created **before** this instant (exclusive). |
| `agent_id` | One id, or up to 20 comma-separated. |
| `status` | One [status](#statuses), or up to 20 comma-separated. Matches the status the call reports now: `queued`, `dialing`, `in_progress` or an ending status. |
| `campaign_id` | One id, or up to 20 comma-separated. |
| `contact_id` | One campaign contact id, or up to 20 comma-separated. |
| `direction` | `inbound` or `outbound`. Browser calls, text chats and realtime sessions are `outbound`. |
| `phone` | The call's `to` or `from`: E.164 (`+919876543210`) or a 10-digit Indian number (`9876543210`). |
| `outcome` | One name from your agents' [`analysis.outcomes`](/v2/analysis#outcomes), or up to 20 comma-separated. `null` matches calls whose `outcome` is `null`. |
| `ids` | Up to 100 call ids, comma-separated. Returns the ones that are your calls and match the other filters, in list order. Unknown ids are left out. |
| `updated_from` | RFC 3339. List by change instead: calls whose `updated_at` is at or after this instant, **oldest change first**. See [sync what changed](#sync-what-changed). |
| `updated_to` | RFC 3339. Upper bound on `updated_at`, exclusive. |

Filters combine with AND. A malformed time, phone or direction, or too many
values, is `400 invalid_request`.

```bash
curl -G https://sandbox.voice.miraiminds.co/v2/calls \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  --data-urlencode "campaign_id=cmp_01K7QAC5N9P4R7S3T6V8W2X4YB" \
  --data-urlencode "status=no_answer,busy" \
  --data-urlencode "from=2026-11-20T00:00:00+05:30" \
  --data-urlencode "to=2026-11-21T00:00:00+05:30" \
  --data-urlencode "limit=100"
```


`next_cursor` is an opaque string; send it back as `cursor` unchanged. See
[pagination](/v2/overview#pagination).

### Paging

Follow `next_cursor` until `has_more` is `false`. A filtered page can hold
fewer calls than `limit`, even none, while `has_more` is `true`. One request
looks at no more than 20,000 calls, then answers with what it found and a
cursor that resumes after the last call it looked at. Never stop on an empty
page; stop on `has_more: false`.

A cursor from a newest-first list can't be used with `updated_from`, or the
other way round (`400 invalid_request`).

### Sync what changed

Every call has `updated_at`: when anything [`GET /v2/calls/{id}`](#get-a-call)
returns last changed. That is the call ending, its transcript, analysis,
post-call processing, recording, flow outcome or a human takeover. Results land
minutes after a call ends, and `updated_at` moves when they do.

1. First run: `GET /v2/calls?updated_from=<start>&limit=100`, following
   `next_cursor` until `has_more` is `false`.
2. Remember the largest `updated_at` you received.
3. Next run: `GET /v2/calls?updated_from=<that value>`.

A call that changes again after you received it is listed again (at least
once), so handle repeats by `id`. Changes from the last few seconds appear on
the next request. The live status between `queued` and the end (`dialing`,
`in_progress`) does not move `updated_at`; the end does. A call last changed
before November 2026 carries the latest time its record holds: created,
started, ended or analysed.

### Time windows

`from`, `to`, `updated_from` and `updated_to` are RFC 3339 instants, in UTC
(`2026-11-20T00:00:00Z`) or with an offset (`2026-11-20T05:30:00+05:30`). The
lower bound includes its instant and the upper bound excludes it: `[from, to)`.
[Count calls](#count-calls), [download your calls](#download-your-calls) and
[how your calls went](#how-your-calls-went) use the same rule, so they cover
the same calls as a list over the same window.

<Note>
Use the list endpoint for reconciliation, reporting and syncing. To drive your
application state, use [webhooks](/v2/webhooks).
</Note>

## Count calls

```http
GET /v2/calls/summary?from=&to=
```

How many calls your workspace has made and taken, without paging through
them. These are the same figures the console's Calls page shows.

| Query param | Description |
| :--- | :--- |
| `from` | Optional. RFC 3339 lower bound on `created_at`, inclusive. |
| `to` | Optional. RFC 3339 upper bound on `created_at`, exclusive. |

Leave both out to count every call. The window works the same way as on
[`GET /v2/calls`](#list-calls), so a count and a list over the same window
cover the same calls.

```bash
curl -G https://sandbox.voice.miraiminds.co/v2/calls/summary \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  --data-urlencode "from=2026-10-01T00:00:00Z"
```

```json title="200 OK"
{
  "object": "call_summary",
  "total": 1240,
  "by_channel": { "phone": 1096, "web": 118, "text": 20, "realtime": 6 },
  "by_direction": { "outbound": 1012, "inbound": 228 },
  "duration_secs": 98412,
  "from": "2026-10-01T00:00:00Z",
  "to": null
}
```

| Field | Type | Description |
| :--- | :--- | :--- |
| `total` | integer | Every call in the window. |
| `by_channel` | object | The same calls split by [`channel`](#the-call-object). The four counts add up to `total`. |
| `by_direction` | object | The same calls split into `outbound` and `inbound`. They add up to `total`. Incoming calls from before mid-October 2026 may be counted as outbound, because their records do not say. |
| `duration_secs` | integer | Total live time across those calls, in seconds. A call that never connected adds nothing. |
| `from`, `to` | string \| null | The window you asked for, in UTC. `null` when you didn't set that side. |

Every count is always present, even when it's zero.

| Status | Code | When |
| :--- | :--- | :--- |
| `400` | `invalid_request` | `from` or `to` is not an RFC 3339 timestamp. |
| `503` | `summary_unavailable` | We couldn't read the totals just now. Try again. Don't read it as zero calls. |

## Download your calls

```http
GET /v2/calls/export?kind=&from=&to=&agent_id=&origin=&campaign_id=
```

Every agent's calls in one streamed file: the console's **Download calls** on
the Calls page. Use it for a bulk copy or a spreadsheet. To page through calls
or sync them, use [`GET /v2/calls`](#list-calls).

| Query param | Description |
| :--- | :--- |
| `kind` | `calls` (default): CSV, one row per call. `conversations`: JSON lines, one call per line with its transcript, results and tool runs. |
| `from`, `to` | RFC 3339. Calls created in `[from, to)`, as on [`GET /v2/calls`](#time-windows). Default: today in India time. At most 31 days. |
| `agent_id` | Only this agent's calls. `404` for an agent that is not yours. |
| `origin` | `all` (default: every call except tests), `api`, `inbound`, `campaign`, `callback`, `web` or `test`. |
| `campaign_id` | One campaign's calls. Only with `origin=campaign`. |

```bash
curl -G https://sandbox.voice.miraiminds.co/v2/calls/export \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  --data-urlencode "kind=calls" \
  --data-urlencode "from=2026-11-10T00:00:00+05:30" \
  --data-urlencode "to=2026-11-17T00:00:00+05:30" \
  -o calls.csv
```

```csv title="calls.csv (first columns)"
call_id,agent_id,agent_name,origin,campaign_id,campaign_name,direction,from,to,created_at,answered_at,ended_at,status,ended_reason,reason_plain,duration_secs,billed_inr,success,summary,…
```

A `calls` row has the call's agent, numbers, status, duration and cost, the
summary, an `outcome` column after `summary` when an agent in the file has
[outcomes](/v2/analysis#outcomes), a `result.<field>` column for every field
your agents collect, the recording link, and then the call's `variables` and
`metadata` as JSON. The recording link opens with your key, or in a browser
signed in to the console.

Times are in India time. The CSV writes them as `YYYY-MM-DD HH:MM:SS`, which
Excel and Google Sheets read as dates and times. The `conversations` file keeps
RFC 3339 with the `+05:30` offset. Numbers are E.164.

| Status | Code | When |
| :--- | :--- | :--- |
| `400` | `invalid_request` | An unknown `kind` or `origin`, a malformed time, a window over 31 days, or `campaign_id` without `origin=campaign`. |
| `413` | `export_too_large` | The file would hold more than 100,000 calls. The message gives the count; split the window. |
| `429` | `rate_limited` | More than six downloads a minute in your workspace, counted together with agent downloads. Wait for `Retry-After`. |

## How your calls went

```http
GET /v2/insights?from=&to=
```

Every call your workspace made and took in a window, read as a whole: campaigns,
incoming callers, one-off calls from your code or the console, and browser
tests. It answers the questions a count can't. How many connected, how many the
agent judged a success, what the calls cost, how fast your agents replied, and
what needs you. These are the figures on the console's **Overview** page.

| Query param | Description |
| :--- | :--- |
| `from` | Optional. RFC 3339 lower bound on `created_at`, inclusive. Defaults to 30 days before `to`. |
| `to` | Optional. RFC 3339 upper bound on `created_at`, exclusive. Defaults to now. |

The window is at most 92 days. Calls count by when they were created, the same
way [`GET /v2/calls`](#list-calls) filters them.

```bash
curl -G https://sandbox.voice.miraiminds.co/v2/insights \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  --data-urlencode "from=2026-10-07T00:00:00+05:30"
```

| Field | Description |
| :--- | :--- |

when there's nothing to divide or measure, never `0`.

| `attention.code` | Severity | What it means |
| :--- | :--- | :--- |
| `wallet` | `act` | Calls didn't start, or were cut off, because the wallet ran out. |
| `inbound_misses` | `act` | People called a number on your telephony account that isn't added to this workspace, so nobody answered. |
| `agent_unavailable` | `act` | Calls reached a number whose agent couldn't take them (unpublished, archived or missing). |
| `throttled` | `watch` | Calls were turned away by a rate or concurrency limit. |
| `failing_calls` | `watch` | A large share of calls failed on our side. We're alerted too. |
| `tool_failures` | `watch` | Tools on your calls are failing often. |
| `short_calls` | `watch` | Callers often hang up within 15 seconds on one agent (`subject`). |
| `number_resting` | `watch` | One of your numbers (`subject`) is resting or cooling down to protect its answer rate. |

| Status | Code | When |
| :--- | :--- | :--- |
| `400` | `invalid_request` | `from` or `to` is not an RFC 3339 timestamp, `from` isn't before `to`, or the window is longer than 92 days. |
| `503` | `insights_unavailable` | We couldn't read the figures just now. Try again. Don't read it as a quiet month. |

MCP clients get the same read as the `get_workspace_insights` tool.
