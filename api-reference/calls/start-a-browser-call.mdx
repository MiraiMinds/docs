A browser call (also called a web call) runs one of your agents with the
user's microphone and speakers. It is the same endpoint as
[Place a call](/api-reference/calls/place-a-call), with two differences in the
body: `"channel": "web"`, and no `to`. Sending `to` with `channel: "web"`
returns `400 invalid_request`, because nothing is dialled.

Call it from your server, where your key lives. The `202` gives you two links
for this one call. Hand them to the page, and the page never sees your key:

| Field | What the page does with it |
| :--- | :--- |
| `ws_url` | Opens it as a WebSocket and streams audio both ways. **Single use**; connect within 5 minutes (`ws_url_expires_at`). |
| `events_url` | Opens it with `EventSource` to show the agent's state and each finished turn. Works for the whole call and an hour after. |

## The audio socket

The page opens `ws_url` with `new WebSocket(ws_url)`. Audio is binary in both
directions: raw PCM, 16-bit signed little-endian, mono, **48,000 Hz**, with no
header. Send 20 ms frames (1,920 bytes) continuously, and send zeros to mute
rather than stopping. When the user interrupts, the server sends the text
message `{"event":"clear"}`: drop any agent audio you have queued but not yet
played. Closing the socket ends the call.

The call stays `queued` until the page connects, then moves to `in_progress`.
If no audio connects before `ws_url` expires, the call ends `failed` with
`ended_reason: "no-media"` and costs nothing.

## The live event stream

```javascript
const events = new EventSource(events_url);
events.addEventListener("transcript.turn", (e) => {
  const { role, text } = JSON.parse(e.data).data;
});
events.addEventListener("call.ended", () => events.close());
```

Events are `agent.state` (`listening`, `processing`, `speaking`, `ended`),
`transcript.turn` (one per finished turn, for both speakers) and `call.ended`,
which is always last. Your server can read the same stream with its key at
[Stream live events](/api-reference/calls/stream-live-events).

## While it runs and after

- **Steer or end it** from your server with
  [Send a live control](/api-reference/calls/send-a-live-control): an
  `instruction` the agent follows from its next reply, or a `close` with a
  goodbye line.
- **Results** arrive as webhooks to `webhook_url`, the same as a phone call.
  The terminal event carries the transcript, the recording link and the
  analysis. See [call results](/v2/webhooks#call-results).
- **Billing** starts when audio goes live and follows the same per-minute rate
  as a phone call.

The [browser calls guide](/v2/web-calls) has a complete page and backend, and
timing options for timed sessions. Every event payload is in
[Live events](/v2/live-events).
